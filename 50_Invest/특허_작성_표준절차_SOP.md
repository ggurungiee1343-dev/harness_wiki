# 특허 작성 표준절차 (SOP)

> **목적**: 발명 분야(기계·전자·소프트웨어·화학·비즈니스방법 등)와 무관하게, 모든 특허 작업에 공통으로 사용하는 절차서. 특정 발명의 세부 기술내용에 종속되지 않도록 범용 원칙만 담는다.
> **성격**: 변리사 정식 검토를 대체하지 않는다. "출원 전 준비 단계에서 Claude Code 세션이 무엇을, 어떤 순서로, 어떤 산출물로 만들어야 하는가"에 대한 작업 절차서다.
> **작성일**: 2026-07-11

---

## 0. 전체 흐름 한눈에 보기

```
Phase 0: 발명신고 인터뷰   → 구조화된 4섹션 질의로 원재료 수집(변리사 재구성 시간 제거)
Phase 1: 발명 정의        → 문제-해결수단-효과를 한 문단으로 압축
Phase 2: 선행기술조사(예비)  → 국내외 DB에서 근접 특허 원문 대조
Phase 3: 청구항 초안       → 발명 유형별 원칙에 따라 독립항+종속항 설계
Phase 4: 명세서 작성       → KIPO 표준 양식 순서로 [0001]~ 번호 부여
Phase 5: 자기방어 논리     → 거절이유 통계 비중에 따라 방어 우선순위 배분
Phase 6: 변리사 제출 패키지 → 검토요청 리스트 + 대비표 + 출처 각주 + 심사가속 옵션 결정
```

각 Phase는 이전 Phase의 산출물을 입력으로 받는 순차 구조이며, Phase 2에서 위협 선행기술이 발견되면 Phase 3으로 되돌아가 청구항을 재설계한다(루프 허용). 발명 건마다 이 SOP를 복제해 새 파일을 만들지 말고, 이 문서 하나를 계속 참조하며 개별 발명의 세부 자료(대비표·청구항 초안 등)는 별도 문서에 둔다.

> **이 SOP의 실증 근거**: 아래 절차는 저자의 경험칙이 아니라, USPTO 통계·학술연구·전문 실무서를 근거로 설계했다. 각 Phase 하단에 근거 자료를 명시한다.

## Phase 0 — 발명신고 인터뷰 (구조화된 원재료 수집)

> **근거**: 기업 IP 실무에서 정형화된 발명신고서(invention disclosure form)는 발명자-변리사 간 정보 손실을 줄이고, 변리사가 처음부터 정보를 재구성하는 시간을 없애 전체 드래프팅 시간을 단축시킨다. 핵심은 "제목·발명자·문제-해결-효과 형식의 간결한 설명"에 집중하고 양식을 길게 만들지 않는 것 — 양식이 길고 복잡하면 발명자 참여 자체가 줄어든다는 것이 실무 컨센서스다.

**표준 4섹션 (이 순서로 질의)**

1. **기본정보** — 발명 명칭(가제), 발명자, 제3자 공개/상용화 이력(공지예외 판단에 필요), 관련 계약(직무발명 여부 등)
2. **선행기술** — 발명자 본인이 아는 관련 기술·경쟁제품·유사 특허(정식 조사 전 예비 인지 수준이라도 기록)
3. **가치 진술** — 이 발명이 해결하는 구체적 문제, 기존 방식 대비 무엇이 새로운가(발명자의 언어로, 이후 Phase 1에서 다시 압축)
4. **상세** — 구현 방식, 변형 가능한 실시예, 아직 검증 안 된 부분

**산출물**: 4섹션이 채워진 원본 노트 (아직 특허 문서 형식 아님 — Phase 1에서 압축)

**참고**: [Invention Disclosure Form Best Practices (Saul Ewing)](https://www.saul.com/insights/article/best-practices-drafting-invention-disclosure-forms), [Invention Disclosure Form Guide (InspireIP)](https://inspireip.com/what-is-invention-disclosure-what-it-means-for-you/)

## Phase 1 — 발명 정의

**산출물**: 요약문 1문단(150~250자), 대표도(텍스트 블록다이어그램)

**체크리스트**
- [ ] 트리거(무엇이 발명을 작동/적용시키는가) — 외부 입력/내부 상태/사용자 조작/조성물 조합 등 발명 유형에 맞게 명시
- [ ] 처리(무엇을 하는가) — 기능 단위로 분해
- [ ] 효과(무엇이 좋아지는가) — 종래 기술 대비 정량/정성 개선점
- [ ] **권한·역할 경계 명시** — 이 발명이 하지 않는 일, 다루지 않는 범위를 먼저 선 긋는다. 경계가 모호하면 청구항이 과욕을 부려 회피설계에 취약해지거나, 반대로 명세서 뒷받침이 안 되는 넓은 청구항이 된다.

**실전 원칙**: 요약문을 먼저 한 문단으로 못 쓰면, 청구항도 못 쓴다. Phase 1이 안 끝난 채 Phase 3(청구항)으로 넘어가면 청구항이 산발적으로 늘어난다.

## Phase 2 — 선행기술조사 (예비조사, FTO 아님)

> **핵심 원칙**: 이 단계는 정식 FTO(자유실시조사)를 대체하지 않는다. 목적은 "출원할 가치가 있는가"를 판단하고 청구항 설계에 반영할 근접 선행기술을 찾는 것.

### 2-1. 검색 DB (국가별, 공통)

| 국가 | DB | 접근법 |
|---|---|---|
| 한국 | KIPRIS (kipris.or.kr) | 키워드+IPC/CPC 조합, 관련 출원인 전수조회 |
| 미국 | USPTO Patent Public Search, Google Patents | 키워드+분류(CPC). Google Patents "Family Applications/Country Status" 섹션이 실질 패밀리 데이터 — 특허 패밀리 확인 시 Cited By/Similar Documents의 타국 번호와 혼동하지 말 것(패밀리 아님) |
| 일본 | J-PlatPat (특허·실용신안검색) | 선택입력 탭, 전문(TX) 키워드 조합. DB별 검색엔진 특이 동작(AND 조합 시 결과가 예상과 다르게 나오는 등)이 있을 수 있으므로, 검색식을 바꿔가며 결과 건수·내용이 합리적인지 항상 재검증할 것 |
| 중국 | CNIPR, Google Patents | 키워드 |
| 국제 | WIPO Patentscope | 키워드, PCT 패밀리 — 1.5억 건 이상 커버 |

### 2-2. 검색 실행 절차

1. **핵심 기능/구성 키워드 3~5개 조합**으로 국가별 1차 검색
2. 결과에서 **도메인 무관 항목 제외** — 다만 제외 판단은 초록만으로 하지 않는다
3. 근접 후보는 **반드시 원문(요약+대표청구항+대표도) 대조** — 초록/AI요약만 보고 "무관" 판단하지 않는다
4. **오인용 검증**: 검색엔진이나 이전 조사가 인용한 문헌번호가 실재하는지, 내용이 실제로 관련 있는지 원문으로 재확인 — 존재하지 않거나 무관한 문헌번호가 인용 목록에 섞여드는 사례가 실제로 있었음

### 2-3. 대비표 작성 (필수 산출물)

발견된 근접 특허마다 **본 발명의 핵심 요소를 축으로** 대비표를 만든다. 축의 개수·이름은 발명마다 새로 설계하되, 최소 아래 4가지는 대부분의 발명에 적용 가능한 공통 축이다.

| 축 | 의미 |
|---|---|
| 입력/트리거 | 무엇이 발명의 동작을 개시시키는가 |
| 처리 방식 | 입력을 어떻게 변환·판단·결합하는가 |
| 출력/결과물 | 무엇이 산출되는가, 어디까지 물리적/기능적으로 미치는가 |
| 검증 가능성 | 결과가 의도대로 실현됐음을 확인할 수단이 있는가 (없다면 없다고 명시 — 이 축이 비어있는 선행기술은 이후 진보성 논거의 재료가 됨) |

이 표를 채우면 "선행기술이 어느 축까지 개시했고, 어느 축을 본 발명이 처음 결합했는가"가 시각적으로 드러나 진보성 논거의 뼈대가 된다.

### 2-4. 선행기술조사의 목적 재확인 (WIPO 가이드 반영)

WIPO Patent Drafting Manual 기준, 선행기술 검색은 다음 두 목적을 동시에 수행한다:
- (a) 발명이 신규성을 상실하지 않았는지 확인
- (b) 선행기술을 **회피하도록 청구항 문언을 조정**하는 재료 확보

→ 선행기술조사는 "떨어뜨리려는" 게 아니라 "청구항을 어떻게 써야 하는가"의 입력값이다. Phase 2에서 위협 문헌이 나오면 즉시 Phase 3(청구항)으로 피드백한다.

**참고**: [WIPO Patent Drafting Manual (2nd ed.)](https://www.wipo.int/edocs/pubdocs/en/wipo-pub-867-23-en-wipo-patent-drafting-manual.pdf)

## Phase 3 — 청구항 초안

### 3-1. 독립항 설계의 범용 원칙

- **구성요소 수와 권리범위는 반비례**: 요소가 많을수록 등록 가능성은 높아지지만 회피설계(경쟁품이 요소 1개만 빼는 것)에 취약해진다. 독립항의 구성요소 수를 "넓게 vs 좁게" 두 안으로 검토하고, 어느 쪽이 선행기술 대비 성립 가능한지를 변리사 확인 항목으로 항상 남긴다.
- **기능식 기재는 상위개념으로, 구체 수단은 종속항으로**: 독립항에는 "무엇을 하는지"까지만 쓰고 "어떤 부품/알고리즘/조성으로 하는지"는 종속항·실시예에 배치한다. 상용 부품명·정확한 수치·특정 알고리즘명은 독립항에 넣지 않는다(권리범위 축소 방지).
- **역할·권한 한정을 명시**: 발명이 처리하지 않는 범위를 청구항 문언에 넣으면, 종래 기술과의 역할 분리가 곧 진보성 논거가 될 수 있다.

### 3-2. 발명 유형별 청구항 구조 — 유형을 먼저 판별할 것

**세부 청구항 패턴(종속항을 어떤 축으로 계층화할지)은 발명 유형에 따라 완전히 다르다.** 아래 표로 유형을 먼저 판별하고, 해당 유형의 원칙만 적용한다 — 다른 유형의 패턴을 섞어 쓰지 않는다.

| 발명 유형 | 청구항 핵심 축 | 독립항에 넣지 말아야 할 것 |
|---|---|---|
| 장치/시스템(기계·전자·IoT) | 구성요소 간 연결관계, 신호/에너지 흐름 | 특정 IC·센서 모델명, 정확한 임계값 수치 |
| 방법/프로세스(제조·제어·알고리즘) | 단계의 순서, 각 단계의 입출력 관계 | 구체적 파라미터 값, 특정 소프트웨어 라이브러리명 |
| 조성물/화학 | 성분과 함량 범위(마쿠시 청구항 등) | 특정 브랜드 원료명, 단일 수치(범위로 기재) |
| 소프트웨어/알고리즘 | 하드웨어와 결합된 구체적 처리 흐름(추상적 아이디어 단독 청구 금지) | 범용 컴퓨터에서 "정보를 처리한다" 수준의 추상적 기재 |
| 비즈니스방법 | 기술적 수단과 결합된 구현(방법 자체만으로는 특허성 약함, 국가별 심사기준 상이) | 순수 상거래 규칙 서술 |
| 디자인 | 물품의 형상·모양·색채 자체 | 기능적 효과 서술(디자인권은 기능이 아닌 외관 보호) |

### 3-3. 종속항 설계 — 범용 카테고리

발명 유형에 무관하게 재사용 가능한 종속항 목적 카테고리:

| 카테고리 | 목적 |
|---|---|
| 예외/실패 상황 대응 | 정상 경로가 아닌 상황(오류·미반응·경계값)에서의 거동을 별도로 청구 |
| 대체 구현수단 | 동일 기능을 다른 수단으로도 구현 가능함을 명시해 회피설계를 차단 |
| 상태 보전 | 전원단절·중단 등 예외 상황에서도 핵심 데이터/상태를 지키는 구성 |
| 신뢰성/검증 강화 | 결과의 정확성·진정성을 추가로 담보하는 구성 |
| 보안/변조방지 | 데이터·장치의 무단 접근·변경을 막는 구성 |
| 확장 실시예 | 상용 부품·환경 스펙 등 구체적 구현 세부사항 |
| 방법항 병행 | 장치/조성물 청구항과 동일 개념을 방법 청구항으로 병행 청구 |

### 3-4. KIPO 공식 작성 원칙 (외부 표준)

- 독립항은 발명의 성질에 따라 적정한 수로 기재
- 종속항은 반드시 인용 항 번호를 명시
- 도면 인용부호는 필요시 청구범위에 기재 가능
- 상세 형식은 특허법 시행령 제5조 기준

참고: [특허청 명세서작성사례안내](https://www.patent.go.kr/smart/jsp/ka/menu/guide/main/GuideMain0208.do)

## Phase 4 — 명세서 작성 (KIPO 표준 양식 순서)

특허법 시행규칙 별지 제15호서식 기준, 아래 순서·번호 매김([0001] 형식)을 그대로 따른다.

1. **서지사항** — 발명의 명칭 / IPC(변리사 확정 요망으로 표기) / 출원인·발명자(공란이면 반드시 "(기재 요망)"으로 명시, 빈칸 방치 금지) / 대리인 / 청구항 수 / 작성일
2. **요약** — Phase 1 산출물 그대로
3. **대표도** — 텍스트 블록다이어그램으로 우선 작성(정식 도면은 변리사/도면사 영역)
4. **특허청구범위** — Phase 3 산출물
5. **명세서**
   - [0001] 기술분야
   - [0002]~ 배경기술 — **종래 기술의 구조적 한계를 구체적으로 서술**(법령·표준 근거 인용 가능하면 권장)
   - 해결하고자 하는 과제 — 번호 매긴 리스트로 명시
   - 과제의 해결 수단 — Phase 3 청구항을 산문으로 재서술
   - 발명의 효과
   - 도면의 간단한 설명
   - 발명을 실시하기 위한 구체적인 내용 — 구성요소별 상세 + **[선행기술과의 관계]** 소섹션(Phase 2 대비표를 명세서 문장으로 전개) + **실시예**(상용 부품명·수치는 여기서만 기재)
6. **참고 — 선행기술 대비표** (변리사 검토용 부록, 본문 명세서와 분리)
7. **변리사 검토 요청사항** (Phase 5·6 산출물)

**실전 원칙**: 서지사항의 `(기재 요망)` 같은 빈칸은 초안 단계에선 정상이지만, **변리사 제출 직전 반드시 빈칸 재검색 실행**(grep 등으로 실제 확인, "아마 채웠을 것"으로 넘기지 말 것).

## Phase 5 — 자기방어 논리 (예상 거절이유 선제 대응)

변리사에게 넘기기 전에, 심사관이 제기할 법한 거절이유를 스스로 시뮬레이션하고 명세서에 반박 논거를 미리 심어둔다.

> **근거— 방어 우선순위는 통계로 정한다**: USPTO 공개 통계(2017~2020 출원 기준) 거절이유 비중은 §103(진보성) 46.9%, §112(기재불비) 24.3%, §102(신규성) 21.3%, §101(대상적격) 7.5%다. 즉 자기방어 문단 작성 시간의 절반 가까이를 **진보성(결합의 곤란성) 논거**에, 그다음을 **청구항 문언의 명확성(기재불비 예방)**에 배분하는 것이 통계적으로 가장 효율적이다. §112 지적은 대부분 **최초 거절통지에서** 나오므로(2차 통지까지 기다리지 않음), Phase 4 명세서 작성 시점에 이미 문언을 다듬어두면 그 자체로 지연 요인 하나를 사전 제거하는 셈이다.
> 출처: [The Most Common Rejections: 102, 103, and 112(b) (Juristat)](https://blog.juristat.com/most-common-rejections)

### 5-1. 표준 거절이유 카테고리와 대응 패턴 (범용, 통계 비중순 배열)

| 거절이유 유형 | 대응 논거 패턴 |
|---|---|
| 신규성/진보성 부정 (근접 선행기술과 중첩) | **관점 구분**: 선행기술과 본 발명이 같은 문제를 다루더라도 접근 관점 자체가 다름을 논증(예: 사전예방 vs 사후대응, 중앙집중 vs 분산) |
| 진보성 부정 (개별 구성요소는 공지) | **결합체 대비 원칙**: 개별 요소가 아니라 "요소들의 결합 전체"를 대비 대상으로 삼도록 명세서에 명시. 종속항은 독립항 전체를 전제하므로 대비 대상도 결합체 전체 |
| Teaching-away 활용 | 관련 업계 표준·통상적 설계 방향이 본 발명과 **반대**를 지향한다면, 그 사실 자체가 "통상의 기술자가 쉽게 도달할 수 없었다"는 진보성 논거가 됨 |
| 기능식 청구항 기재불비 (실시가능·뒷받침 요건) | 기능적 표현에 대해, 명세서에 **구체적 판별 원리(수식·알고리즘·공정조건 등)**를 실시예로 제시해 통상의 기술자가 과도한 실험 없이 구현 가능함을 뒷받침 |
| 주지관용기술 지적 | 유사 구성이 이미 공지된 경우, "그 구성 자체는 인정하되, 본 발명 고유의 부가 결합이 차별점"으로 좁혀서 방어 |

### 5-2. 절차

1. 본 발명과 가장 근접한 선행기술 1~2건을 선정
2. 그 문헌을 근거로 심사관이 제기할 거절이유를 스스로 문장으로 써본다("~이유로 신규성이 부정될 수 있다")
3. 위 표의 대응 패턴 중 적합한 것을 골라 반박 논거를 명세서 [00xx] 문단으로 삽입 (사후 대응이 아니라 **사전에 명세서 안에 심어두는 것**이 핵심 — 의견서 단계에서 새로 주장하면 신규사항 추가 리스크가 있음)
4. 명세서에 "선행기술과의 관계"라는 별도 소제목을 만들어 이 논거들을 모아둔다

## Phase 6 — 변리사 제출 패키지 구성

### 6-1. 필수 포함 항목

- [ ] 서지사항 빈칸 전수 확인 (`(기재 요망)` 검색으로 실제 확인)
- [ ] 청구항 전수 재검토 — **부품명·수치·특정 알고리즘명이 독립항에 없는지 전수조사**. 상위개념화 이후에도 일부 종속항에 구체 정보가 우회통로 형태로 남아있지 않은지 전 청구항을 훑을 것
- [ ] 선행기술 대비표 (Phase 2 산출물)
- [ ] 심사관 예상 거절이유 및 대응 논거 (Phase 5 산출물)
- [ ] **변리사 검토 요청사항 리스트** — 아래 표준 항목을 기본으로 하고 발명별로 추가
- [ ] 출처 각주 — 인용한 모든 선행문헌 번호를 한 곳에 모아 정리 (오인용 방지)

### 6-2. 변리사 검토 요청사항 — 표준 항목 (재사용 템플릿)

1. 정식 FTO (KIPRIS·WIPO·USPTO·CNIPR 등 실제 관련국) — 예비조사 대체 아님을 명시
2. 핵심 감시 대상 선행기술 N건에 대한 청구항 대 본 발명 침해 여부 정밀 대조
3. 대비표 축의 신규성·진보성 성립 여부, teaching-away 논거 채택 적정성
4. 독립항 경량화(넓은 독립항) vs 현행(좁지만 안전한 독립항)의 트레이드오프 확인
5. 해외 출원(PCT) 확장 시 국가중립적 문언 필요 여부
6. 방법항이 장치/조성물 청구항의 세부 요소를 충분히 커버하는지
7. 권리범위 협소화 타개 전략 확인 — 아래 3종 전략의 우선순위:
   - **(a) 상위개념화 우선 채택** — 즉시 청구항 본문 반영
   - **(b) 분할출원** — **등록결정 이후에만** 실행하는 조건부 옵션(출원 초기 선집행 금지)
   - **(c) 복수 독립항 병기** — 단일성 요건 충족 시 **한 출원 내** 처리 원칙. 별건 분리(비용 2배)를 변리사가 권유하면 단일성 위반 등 법적 근거를 요구하고, 근거 없는 분리는 채택하지 않음

### 6-3. 비용 통제 원칙 (전 특허 공통 적용)

- 별건 출원(추가 출원료) 권유에는 항상 "왜 한 출원에 못 담는가"의 법적 근거를 먼저 요구한다
- 분할출원은 보험 성격의 사후 카드이지 초기 전략이 아니다 — 등록결정 전 실행 금지
- 특허의 사업화 목적을 사전에 명시해두면(소송무기 vs 협상카드/방패) 변리사와의 논의가 방향성을 잃지 않는다

## 부록 B — Phase별 실패 시 되돌아갈 지점 (루프 규칙)

- Phase 2에서 결합체 전체를 개시하는 선행기술 발견 → **Phase 1로 복귀**, 발명 정의 자체 재검토
- Phase 2에서 일부 요소만 겹치는 선행기술 발견 → **Phase 3으로 복귀**, 겹치는 요소를 종속항으로 내리고 독립항에서 결합 방식을 새 신규성 근거로 재설정
- Phase 4 작성 중 청구항 문언이 명세서로 뒷받침 안 됨을 발견 → **Phase 3으로 복귀**, 청구항 문언 조정 또는 명세서에 실시예 보강
- Phase 6 최종 점검에서 독립항에 상용 부품명·수치 잔존 발견 → **Phase 3으로 복귀**, 전수조사 후 상위개념화

## 부록 C — 이 SOP 자체의 갱신 규칙

이 문서는 **특정 발명이 아니라 절차 자체**를 다룬다. 개별 발명 작업(예: 어선 안전, 항만 안전 등)에서 얻은 세부 교훈은 이 문서에 직접 넣지 않고, 해당 발명의 개별 자료 문서에 남긴다. 다만 그 교훈이 **발명 유형에 무관하게 재사용 가능한 절차/원칙**으로 일반화될 수 있다고 판단되면, 이 문서를 갱신해 반영한다. 새 발명마다 별도 SOP를 만들지 말고 이 파일 하나에 축적한다.

## 부록 D — 심사 지연을 줄이는 절차적 선택지 (Phase 6에서 결정)

> **근거**: USPTO 표준 심사는 출원부터 최종처분까지 평균 25개월(2회 이상 거절통지 시 3년 이상)이 걸린다. 반면 아래 제도들은 절차 선택만으로 이 기간을 실질적으로 단축시킨다 — 명세서 품질과 무관하게 확보되는 시간 단축이므로, Phase 6에서 반드시 검토 항목으로 넣는다.

| 제도 | 효과 | 조건 | 비용 |
|---|---|---|---|
| **Track One (우선심사)** | 평균 최종처분 약 5개월(vs 표준 25개월), 최초통지 최단 3개월 | 독립항 4개 이하, 전체 청구항 30개 이하, 다중종속항 불가 | 추가 관납료(정규 기업 약 $4,515, 소기업 약 $1,806) |
| **PPH (특허심사하이웨이)** | 최초통지까지 평균 약 7.5개월(비-PPH의 절반 수준) | 한 IP청(예: KIPO)에서 등록 가능 판단을 받은 청구항이 있어야 타국(USPTO 등)에서 이용 가능 | 추가 관납료 없음 |
| **Track One + PPH 병행** | 한 국가에서 우선심사로 먼저 등록 가능 판정을 받은 뒤, 그 결과로 타국 PPH를 신청해 해외 확장 속도까지 동시에 단축 | 두 조건 결합 | Track One 비용만 |
| First Action Interview Pilot | 최초 거절통지 전 심사관과 사전 인터뷰 — 최초통지 허용률을 크게 높이는 효과 보고됨 | 프로그램 참여 가능 기술분야 확인 필요 | 추가 관납료 없음 |

**적용 판단**: 사업화 일정이 급하지 않으면 표준심사로 충분하나, 경쟁사 대응·투자 유치·정부조달 스펙 등재처럼 **등록 시점 자체가 사업적으로 중요한 경우** Track One을 기본으로 검토하고, 해외출원 계획이 있으면 PPH 병행을 변리사 검토 요청사항에 명시한다.

**참고**: [Patent Prosecution Highway (USPTO)](https://www.uspto.gov/patents/basics/international-protection/patent-prosecution-highway-pph-fast-track), [Track One Prioritized Examination (PowerPatent)](https://powerpatent.com/blog/track-one-prioritized-examination-a-good-choice-for-patent-applicants)
