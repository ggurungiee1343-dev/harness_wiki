# 📚 논문 워크플로우 가이드

> Hermes3 시스템에서 논문/연구 작업을 위한 명령어 모음 및 워크플로우.
> 이 문서는 지속 업데이트 대상입니다.

---

## 1. 논문 폴더 구조

```
wiki/
├── 20_Research/      # 기존: 일반 연구 자료 (논문 인용/참고용)
├── 30_Journal/       # 학술지/저널 clipping
├── 40_Thesis/        # ⭐ 논문 초안, arXiv stub notes, 논문 분석 결과
└── 50_Invest/        # 투자 관련 자료
```

**40_Thesis**는 논문 작업의 중심 허브:
- `ingest` → LLM 자동 분류 시 `40_Thesis` 선택 가능
- `/paper review wiki/40_Thesis/파일.md` → 논문 검토 가능
- `/reduce wiki 40_Thesis` → FTS5 검색으로 특정 논문 질문

---

## 2. 사용 가능한 명령어

### 논문 검색
| 명령어 | 기능 | API |
|--------|------|-----|
| `/searchpaper [키워드]` | 학술 논문 검색 | OpenAlex (무료, 전분야) |
| `/ask` + 논문 URL | 특정 논문 분석 요청 | Hermes LLM |

### 논문 관리 (`/paper`)
| 하위 명령어 | 기능 |
|------------|------|
| `/paper list` | 저장된 논문 목록 |
| `/paper show [id]` | 논문 상세 조회 |
| `/paper bundle [id1] [id2] ...` | 여러 논문 번들로 묶기 |
| `/paper claims [번들id]` | 번들에서 핵심 주장 추출 |
| `/paper compare [id1] [id2]` | 두 논문/번들 비교 |
| `/paper save [번들id]` | 번들을 마크다운으로 저장 (→ 20_Research/) |
| `/paper review [문서/텍스트]` | 논문/초안 학술 검토 |
| `/paper humanize [텍스트]` | 법학/학술 문체 변환 |
| `/paper draft [주제]` | 논문 초안 생성 (개요→초안→문체 3단계) |

### 자료 Ingestion
| 명령어 | 기능 |
|--------|------|
| `/ingest` | Clippings/ 내 PDF/링크 → LLM 분류 → MD 저장 |
| `/reduce [디렉토리] [질문]` | 저장된 문서 대상 질의응답 (FTS5 + LLM) |

### 검색
| 명령어 | 기능 |
|--------|------|
| `/search [질의어]` | FTS5 전문 검색 (세션/결정/핸드오프) |
| `/fs [질의어]` | `/search` alias |

## 2.5 연구 워크플로우 철학: 분할 명령어 체계

> Hermes3의 연구 워크플로우는 **통합 파이프라인(All-in-One)이 아닌 분할 명령어(Command-per-Step) 체계**를 채택한다.
> 이는 Karpathy 스타일의 "파이프라인 통합" 접근법과 달리, 1인 연구 환경에 최적화된 결정 중심 설계다.

### 왜 분할인가?

| 이유 | 설명 |
|------|------|
| **결정 지점** | 각 단계마다 "진행할까?" 판단 가능. 검색 결과가 별로면 ingest 안 함 → 쓰레기 누적 방지 |
| **에러 격리** | 검색은 성공했는데 분석에서 터져도 검색 결과는 살아있음. 재시도 비용 최소화 |
| **단일 책임** | `/searchpaper`는 검색만, `/ingest`는 저장만. 각자 한 가지 책임 → 코드 단순, 유지보수 쉬움 |
| **투명성** | 각 단계의 결과를 보고 다음 행동을 결정. 블랙박스 없음 |

### 연구 워크플로우 흐름도

```
🧭 검색 (/searchpaper [키워드])
    │
    ├── 결과 보고 "별로네" → ✋ STOP (토큰/시간 0 소모)
    │
    └── "이건 볼만하네"
         │
    📄 초록 확인 (/ask + arXiv URL)
         │
         ├── "내용이 없네" → ✋ STOP
         │
         └── "논문에 쓸만하다"
              │
    💾 저장 (PDF → Clippings/ → /ingest → 40_Thesis)
              │
         🔬 심층 분석 (/reduce wiki/40_Thesis/"요약해줘")
              │
         🔗 종합 (/paper bundle + /paper compare)
```

### 각 결정 포인트 상세

| 단계 | 명령어 | 결정 질문 | STOP 조건 |
|------|--------|-----------|-----------|
| **1. 검색** | `/searchpaper AI agents 2026` | 결과에 흥미로운 논문이 있는가? | 전부 별로면 여기서 종료 |
| **2. 초록** | `/ask https://arxiv.org/abs/...` | 본문을 읽을 가치가 있는가? | 방법론/결과가 약하면 종료 |
| **3. 저장** | `PDF → /ingest` | 이 논문을 영구 보관할 가치가 있는가? | 간단 참고용이면 저장 안 함 |
| **4. 분석** | `/reduce wiki/40_Thesis/파일.md` | 심층 이해가 필요한가? | 단순 인용용이면 여기서 STOP |
| **5. 종합** | `/paper bundle`, `/paper compare` | 여러 논문 연결/비교가 필요한가? | 단일 논문이면 불필요 |

### 통합 파이프라인과의 비교

| 항목 | 통합 파이프라인 (ex: `/yt-pipeline`) | 분할 명령어 (Hermes3) |
|------|--------------------------------------------------|----------------------|
| 적합 환경 | 주 20건 이상 mass research, 무조건 저장 | 선별적 연구, 필요할 때만 |
| 결정 여부 | 자동 진행 (중간 결정 없음) | 각 단계 검토 후 결정 |
| 에러 영향 | 한 군데 터지면 처음부터 | 한 단계만 재시도 |
| 코드 복잡도 | 높음 (분기/상태 관리) | 낮음 (각 명령어 독립) |
| 유연성 | 파이프라인 재구성 어려움 | 순서/조합 자유로움 |
| 투명성 | 블랙박스 (결과만 봄) | 각 단계 결과 확인 가능 |

### 응용: 체인 사용

분할이지만 연속 사용은 가능. 아래처럼 순차 입력하면 사실상 파이프라인:

```
/searchpaper AI agent frameworks 2026      ← 검색
→ 결과 보고 관심 URL 확인
→ /ask https://arxiv.org/abs/XXXX.XXXXX    ← 초록 확인
→ PDF 다운로드 → /ingest                   ← 저장
→ /reduce wiki/40_Thesis "요약해줘"        ← 분석
```

한 줄 명령어로 합칠 필요가 없을 뿐, 연속 실행은 이미 파이프라인이다.

## 3. 토큰 절약 전략

### 기본 원칙: **초록(Abstract) 우선, 선택적 심층 분석**

```
🔍 검색  →  📄 초록만 fetch (~200 tok)  →  📌 40_Thesis/stub
                                              ↕ 필요시
                                     🔬 Full PDF 분석 (~5K tok)
```

### 전략별 상세

| 전략 | 방법 | 절약 효과 | 언제 사용 |
|------|------|----------|----------|
| **초록 우선** | arXiv/OpenAlex API로 초록만 취득 | ~95% (20K→0.2K tok) | 초기 탐색, 브라우징 |
| **References 생략** | LLM에게 "References 제외" 지시 | ~30-40% | 참고문헌이 불필요할 때 |
| **로컬 Gemma4 분류** | 분류/요약만 Gemma4로 처리 | DeepSeek 0원 | 분류 단계 (항상) |
| **질문 중심 분석** | "전체 요약" 대신 "X에 대해 설명" | ~50-80% | 특정 주제만 궁금할 때 |
| **Chunked 분석** | PDF를 3-5 chunk로 나누어 순차 처리 | ~30% | 초장기 논문 (>30 page) |

### 권장 워크플로우

1. `/searchpaper [키워드]` → 관심 논문 식별
2. `/ask https://arxiv.org/abs/XXXX.XXXXX 초록 요약해줘` → 초록 확인
3. 관심 있으면: PDF 다운로드 → Clippings/ → `/ingest` → `40_Thesis` 선택됨
4. 심층 분석: `/reduce wiki 40_Thesis "이 논문의 핵심 주장과 방법론 설명해줘"`
5. 여러 논문 종합: `/paper bundle [id1] [id2]` → `/paper claims` 또는 `/paper compare`

## 4. NotebookLM 병행 전략

`/ingest`의 한계:
- PDF 링크(URL)는 추출 불가 (`get_text()` 한계)
- 복잡한 표/수식은 깨짐

이런 경우 NotebookLM에 원본 PDF를 넣고:
1. NotebookLM에서 요약/질문
2. 핵심 내용만 Hermes로 복사 → `40_Thesis/`에 수동 저장

## 5. arXiv 자동화 (향후 계획)

| 기능 | 상태 | 비고 |
