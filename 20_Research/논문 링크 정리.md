## 📋 논문 분석 및 우리 시스템 관련성

### 🅰️ 메모리 시스템 (1, 2, 5)

| # | 논문 | 관련도 | 이유 |
|:-:|------|:------:|------|
| **1** | **Selective QA over Conflicting Multi-Source Personal Memory** | ⭐⭐⭐⭐⭐ | **가장 직접적.** 우리 Vault + Clippings + session DB + FTS5가 정확히 "multi-source personal memory"임. 충돌 해소 + 기권(abstention) 전략 — 우리 ingest/reduce 파이프라인에 바로 적용 가능한 벤치마크 방법론 |
| **2** | **MMPO (Meta-Cognitive Memory Policy Optimization)** | ⭐⭐⭐⭐ | 재귀적 요약에서 "belief deviation" 문제 분석 — 우리 `/reduce`가 long-horizon 세션에서 정보 손실되는 현상과 정확히 일치 |
| **5** | **Control Architecture for Training-Free Memory Use** | ⭐⭐⭐⭐⭐ | **Training-free = 우리랑 같은 조건.** "when to trigger memory, when to trust it, how to maintain" — 이게 우리 ingest 분류/검색/reduce 파이프라인의 정확한 설계 문제 |

### 🅱️ 하네스 엔지니어링 (3, 6, 8)

| # | 논문 | 관련도 | 이유 |
|:-:|------|:------:|------|
| **3** | **AEvo (Harnessing Agentic Evolution)** | ⭐⭐⭐⭐⭐ | "fixed hand-designed procedures vs general-purpose agents" — 우리 분할 명령어 체계가 정확히 이 스펙트럼 중간. "stable interface for organizing evidence" 부재 문제 -> 우리 skill 시스템이 이걸 해결하려는 시도 |
| **6** | **SemaClaw: Towards General-Purpose Personal AI Agents** | ⭐⭐⭐⭐⭐ | **번역: "하네스 엔지니어링으로의 패러다임 전환"**. OpenClaw (2026 초) 이후 수백만 사용자가 개인 AI 에이전트를 일상에 배치 — 우리 Hermes 시스템의 정확한 포지셔닝. Harness engineering = prompt engineering의 진화 |
| **8** | **DemoEvolve: Overcoming Sparse Feedback in Agentic Harness Evolution** | ⭐⭐⭐⭐⭐ | Harness evolution에서 sparse feedback 문제 — 우리 시스템이 `/exec`/`/reduce` 명령어로 에이전트 행동 구조를 수정하는 패턴과 정확히 일치 |

### 🅲 보안 (4, 7)

| # | 논문 | 관련도 | 이유 |
|:-:|------|:------:|------|
| **4** | **OEP: Poisoning Self-Evolving LLM Agents** | ⭐⭐⭐⭐ | "locally correct but semantically plausible experience → harmful generalization" — 우리가 이미 한 `/reduce` 보안 감사(3계층 방어)를 더 정교화할 수 있는 이론적 기반 |
| **7** | **Hidden in Memory: Sleeper Memory Poisoning** | ⭐⭐⭐⭐ | 문서/웹/저장소를 통한 지연성 메모리 오염 — 우리 ingest 파이프라인이 외부 문서(PDF/클리핑)를 자동 ingest하므로 이 공격 벡터에 직접 노출됨 |
