# Hermes Codebase Harness 가이드

## 1. 개요 (Definition)
**Hermes Codebase Harness**는 대규모 코드베이스와 디렉토리 환경에서 AI 에이전트(헤르메스 봇)가 길을 잃지 않고 정확히 문맥(Context)을 파악하여 작업할 수 있도록 돕는 **'컨텍스트 최적화 엔진'**입니다. Anthropic사의 Claude Code 아키텍처 철학을 바탕으로 제작되었으며, `modules/hermes_context_builder.py`가 그 핵심을 담당합니다.

이 모듈은 AI가 폴더를 이동하거나 문서를 읽을 때마다 **배경지식 조립**, **노이즈 파일 필터링**, **디렉토리 맵 자동 생성**을 수행하여 컨텍스트 윈도우의 낭비를 막고 속도를 비약적으로 높여줍니다.

---

## 2. 핵심 기능 상세 및 사용법

### A. 계층적 동적 컨텍스트 (Hierarchical Context)
- **작동 원리**: 헤르메스가 특정 파일을 읽거나 수정하려 할 때, 그 파일이 위치한 폴더부터 최상위 루트 디렉토리까지 거슬러 올라가며 `HERMES.md` (또는 `README.md`) 가이드라인 파일들을 전부 모아 읽습니다.
- **분석적 장점**: 루트에는 "프로젝트 전체 아키텍처 및 코딩 컨벤션"을 적어두고, 하위 폴더에는 "해당 모듈만의 세부 규칙"을 적어둘 수 있습니다. 이를 통해 AI는 불필요한 전체 문서 탐색 없이, 자신이 현재 위치한 곳의 '맥락'만을 가장 최적화된 형태로 주입받게 됩니다.
- **사용법**: 
  1. 관리하고 싶은 폴더 안에 `HERMES.md` 파일을 생성합니다.
  2. "이 폴더의 코드들은 반드시 클래스 기반으로 짜야 해" 또는 "이 폴더의 파일은 무조건 JSON 포맷이어야 해" 같은 지시사항을 적어둡니다.

### B. 코드베이스 요약 맵 (Codebase Map)
- **작동 원리**: 헤르메스가 폴더 목록을 조회(`[LIST: /경로]`)할 때, 멍청하게 원본 파일명만 나열하는 것이 아니라 폴더인지 파일인지 구분하고, 하위 폴더의 아이템 개수까지 세어서 "시각적 지도(Map)" 형태로 정리해 LLM에 전달합니다.
- **분석적 장점**: 에이전트는 무작정 모든 디렉토리를 열어보지 않아도, "아, 이 폴더 안에는 파일이 10개 있구나, 저 폴더에는 0개구나"를 직관적으로 깨닫고 검색 전략을 영리하게 세우게 됩니다.

### C. 노이즈 필터링 (`.hermesignore`)
- **작동 원리**: `.gitignore`와 완벽히 동일한 원리입니다. 헤르메스 루트 폴더에 위치한 `.hermesignore` 파일에 읽지 말아야 할 파일 패턴을 정의합니다.
- **분석적 장점**: AI가 `__pycache__`나 바이너리 캐시 파일, 로그 파일(`.log`) 등을 억지로 읽으려다가 토큰 제한을 초과하거나 타임아웃 오류가 발생하는 현상을 원천적으로 차단합니다. 
- **사용법**: `.hermesignore` 파일 안에 무시할 확장자(예: `*.pyc`)나 디렉토리명(예: `node_modules`)을 줄바꿈하여 적어두면 끝입니다.

## 3. "자기진화하는 AI" 패러다임과 적용 (분석)

현재 박사님께서 직접 "Antigravity AI"를 통해 헤르메스 봇의 시스템을 개조하고 계십니다. 여기서 중요한 철학적 질문이 발생합니다.
> *"내가 Antigravity로 고치면, 헤르메스 본인은 그 경험을 기억하지 못하는 것 아닌가? 이러면 헤르메스가 스스로 성장하는 에이전트가 되는 길이 막히는 것 아닌가?"*

이 문제를 해결하기 위해 이번에 도입된 것이 바로 **Hermes Codebase Harness (`HERMES.md`) 구조**입니다.

### 💡 "코드 자체가 기억이 되게 하라" (Code-as-Memory)
Antigravity나 사용자가 외부에서 봇의 구조를 뜯어고친 경험치와 노하우를 `harness_memory.json` 같은 단기 휘발성 대화 버퍼에 담아두면, 일정 시간이 지나면 결국 잊혀지거나 컨텍스트에서 밀려납니다. 

하지만 이번 업데이트를 통해, 변경된 아키텍처나 작업 규칙을 **해당 폴더의 `HERMES.md`** 나 **위키 (`스크립트 정보.md`)**에 기록해 두게 되었습니다. 

헤르메스는 작업에 돌입할 때마다 `ContextBuilder`를 통해 자신의 코드가 담긴 폴더의 `HERMES.md`를 **스스로 다시 읽어들입니다.** 즉, 누군가가 밖에서 자신의 뇌 구조를 바꿔놓았더라도, 헤르메스는 자신의 폴더에 적힌 '스스로에 대한 설명서(Meta-Knowledge)'를 읽음으로써 바뀐 자신을 완벽하게 재인지(Self-Awareness)하게 됩니다.

### 예방책 및 행동 강령
1. **Antigravity로 작업한 후**: 항상 그 작업 요약이나 새로 정립된 규칙을 헤르메스 내부의 `HERMES.md`나 옵시디언 위키 파일로 정리하여 저장하게끔(문서화) 지시하십시오.
2. **헤르메스의 자가 학습**: 헤르메스는 스스로를 제어할 때 그 문서들을 동적으로 로딩하므로, 박사님이 Antigravity와 나눈 대화와 깨달음이 고스란히 헤르메스의 "장기 구조적 기억(Long-term Architectural Memory)"으로 이관됩니다.
