## 배경

텔레그램 봇의 일반 텍스트 메시지 처리(LLM 자율 응답)에서 `[RUN_CMD:]` 태그로 실행하는 Bash 명령어가 `/Users/bluesea/Applications/Mjauto/Scripts/` 경로로 고정되어 있었다. 이로 인해 LLM이 사용자에게 "명령어는 반드시 Scripts/ 경로 내에서 실행됩니다"라고 응답하여 실제 필요한 경로에 접근하지 못하는 문제 발생.

## 변경 내용

### 1. executor.py — cwd 경로 확장

**파일:** `modules/executor.py` (line 166)

| 항목 | 변경 전 | 변경 후 |
|------|---------|---------|
| `cwd` | `/Users/bluesea/Applications/Mjauto/Scripts` | `/Users/bluesea` |

이제 `[RUN_CMD: ...]` 태그로 실행되는 모든 Bash 명령어는 **홈 디렉토리(`/Users/bluesea`)** 기준으로 실행되며, 전체 파일 시스템에 접근 가능.

### 2. HELP_TEXT — 경로 안내 업데이트

**파일:** `hermes_local.py` (lines 108, 140-142)

- `/exec` 설명에 `🤖 AI 자율 에러 수정 + 홈 디렉토리 기반 Bash 실행`으로 변경
- 📌 **작업 경로 안내** 섹션 추가:
  - `/exec` 명령어: **홈 디렉토리(/Users/bluesea)** 기준 실행 (전체 접근 가능)
  - 파일 명령어(/delete, /rename 등): 허용 경로 내에서만 작동 — Applications/, hermes/, .hermes/

## 파일 권한 구조 (최종)

```
┌─ /exec (LLM 자율 Bash 실행)
│   └─ 기준 경로: /Users/bluesea (전체 접근)
│       └─ execute_bash_command() → subprocess.run(cwd="/Users/bluesea")
│
├─ /delete, /rename, /list, /move, /copy, /create, /read (파일 조작 명령어)
│   └─ 허용 경로: 3개 BASE
│       ├─ /Users/bluesea/Applications
│       ├─ /Users/bluesea/hermes
│       └─ /Users/bluesea/.hermes
│
└─ secure_path() 검증 로직: 모든 파일 명령어는 위 3개 경로 내에서만 작동
```

## 텔레그램 사용 예시

```bash
# ✅ 가능 (전체 접근)
/exec ls -la /Users/bluesea
/exec cat ~/hermes/README.md

# ✅ 가능 (허용 경로)
/delete /Users/bluesea/Applications/test/temp.txt
/rename /Users/bluesea/hermes/old.md new.md

# ❌ 불가능 (허용 경로 외)
/delete /Users/bluesea/Documents/private.txt
```
