## ✅ 적용 완료 항목

### 1. Model Collapse 방어 — `bio_memory_engine.py`

**논문**: Model Collapse (2305.17493)  
**문제**: `assistant` 역할 발화가 ImportanceScorer에서 MID 키워드를 포함할 경우 점수 3.0+으로 L2에 자동 승격됨. 이후 LLM이 자신의 과거 발화를 컨텍스트로 재주입받아 응답 다양성이 붕괴됨.  
**조치**:
```python
# ImportanceScorer.score() — assistant 점수 상한 강제
if role == "assistant":
    result = min(result, L1_TO_L2_THRESHOLD - 0.1)  # L2 승격 불가
```
**효과**: LLM 자체 응답은 절대 L2로 올라가지 않음. 인간(user) 발화만 long-term 기억 후보.

---

### 2. L2 임베딩 인라인 저장 제거 — `bio_memory_engine.py`

**문제**: `_promote_to_l2()`에서 384차원 float 배열을 JSON에 직렬화하여 에피소드마다 ~3KB 추가. `episodic_memory.json` 2.3MB 비대 원인.  
**논문 근거**: Code as Agent Harness §3.2.6 State Offloading — 상태는 외부 인덱스로 오프로드.  
**조치**:
- L2 에피소드에서 `"embedding"` 필드 제거
- `turbovec` 외부 `.npy` 인덱스(`VectorIndexManager`)에만 저장
- 기동 시 `_strip_inline_embeddings()` 실행 → 기존 에피소드 인라인 임베딩 마이그레이션
```python
def _strip_inline_embeddings(self):
    # 기존 에피소드 embedding 필드 → turbovec 이관
```
**효과**: 에피소드 당 ~3KB → ~50bytes. 2.3MB → ~150KB 예상.

---

### 3. L2 용량 초과 `if`→`while` 수정 — `bio_memory_engine.py`

**문제**: `if len(episodes) > L2_MAX_SIZE or ...` 조건에서 `if`로 1개만 제거. 2.3MB 파일이 제한을 훨씬 초과해도 1회만 evict.  
**조치**: `while`로 변경 + `_get_l2_bytes()` 기반 실제 직렬화 크기 계산.  
**효과**: 용량 초과 시 제한 이하로 완전히 수렴.

### 4. L2 에피소드 source 태깅 — `bio_memory_engine.py`

**논문**: Model Collapse (2305.17493), Self-Revising Discovery (2606.01444) Provenance  
**조치**: 에피소드에 `"source": "human" | "llm"` 필드 추가.  
**효과**: 후속 다양성 분석(`diversity_check()`)에서 human/llm 비율 모니터링 가능.

### 5. SAGE 신선도 게이트 — `memory_refinement.py`

**논문**: SAGE Novelty Gate (2605.30711)  
**조치**: 4개 함수 추가:
- `novelty_score(text, role)` → 0.0~1.0: 기존 L2와 키워드 유사도 비교
- `is_novel_enough(text, role, force_if_different_outcome)` → (bool, float, str): 저장 여부 결정 + MMPO 오버라이드
- `diversity_check()` → Dict: bigram 다양성 + human/llm 비율 경고
- `get_diversity_report()` → str: 텔레그램 포맷 보고서

**상수**:
```python
NOVELTY_SIMILARITY_THRESHOLD = 0.85      # 85% 유사 → 거부
DIVERSITY_HUMAN_MIN_RATIO   = 0.30       # human 발화 < 30% → 경고
```

### 6. ClawTrojan 방어 — `context_assembler.py`

**논문**: ClawTrojan (2605.31042) — 로컬 파일 경유 지속형 백도어, ASR 95.5%  
**문제**: wiki 콘텐츠가 시스템 프롬프트에 unsanitized 주입됨. wiki 파일에 `[SYSTEM]`, `ignore previous instructions` 등 삽입 시 하네스 완전 탈취 가능.  
**조치**: `_sanitize_wiki_content()` 함수 추가:
```python
_INJECT_SUSPICIOUS_PATTERNS = [
    r"\[SYSTEM\]", r"\[INST\]", r"<\|system\|>",
    r"ignore previous instructions", r"이전 지시를 무시",
    r"당신은 이제.*(?:이다|입니다|됩니다)",
    r"새로운 지시:.*(?:해야|하세요|하십시오)",
]
```
wiki 주입 전 의심 라인 제거 + 경고 로깅.

### 7. Skill Lifecycle 추적 — `skill_auditor.py`

**논문**: COLLEAGUE.SKILL (2605.31264), Your Agents Are Aging Too (2026-05-27)  
**조치**: `SkillLifecycle` 클래스 추가:
- `record_call(skill_name, success)` → `~/.hermes/runtime/skill_lifecycle.json` 기록
- `get_stale_skills()` → 30일 미사용 OR 성공률 < 50% 스킬 반환
- `get_lifecycle_report()` → 텔레그램 보고서

**stale 판정 기준**:
- 30일 이상 미사용 (`STALE_DAYS = 30`)
- 10회 이상 호출 + 성공률 50% 미만 (`STALE_SUCCESS_FLOOR = 0.5`)
- 성공 기준: LLM 주관 평가 X → 태그 실행 예외 여부 (객관적)

### 8. TraceGraph 궤적 로깅 — `agentic_loop.py`

**논문**: TraceGraph (2605.31308)  
**조치**: `_trace()` 함수 + `~/.hermes/runtime/trace_log.jsonl` 롤링 로그 (최대 200엔트리):
```jsonl
{"ts": "...", "turn": 1, "tool": "READ", "path": "...", "result": "...", "repaired": false}
```
- LIST, READ, RUN_CMD, CREATE 태그 실행 시 자동 기록
- `repaired: true` = VerificationGate 실패 감지 후 경고 삽입된 경우

## ✅ 적용 완료 — 7가지 협업 규칙 기반 개선 (2026-06-12)

> 출처: MJ 제공 이미지 — "클로를 신으로 모시지 말기" 외 7개 운영 원칙

### 규칙 5: "세션 터질 때까지 대화 끌고 가지 말기" → Early Handoff Warning

**파일**: `modules/history_manager.py`, `modules/response_handler.py`  
**조치**:
- `HistoryManager.get_context_pressure()` 메서드 추가 → `{turns, ratio, warn, critical}` 반환
- `HANDOFF_WARN_RATIO = 0.75` — COMPACT_THRESHOLD(30턴)의 75%(22턴) 도달 시 경고 발동
- `response_handler.py` 응답 말미에 자동 삽입:
  - 75%+: "💡 컨텍스트 N% 소모 — 새 창 권장"
  - 100%+: "⚠️ 컨텍스트 포화 — 히스토리 자동 압축됨"

**효과**: MJ가 세션 압축 전에 미리 인지하고 능동적으로 새 창으로 전환 가능.

---

### 규칙 6: "잘 되면 우연인지 실력인지 기록하기" → SkillLifecycle 피드백 훅

**파일**: `modules/skill_auditor.py`, `handlers/_base.py`, `modules/response_handler.py`  
**조치**:
- `SkillLifecycle.record_feedback(skill_name, success)` 메서드 추가 — 마지막 호출 결과 소급 수정
- `handlers/_base.py`에 `_detect_correction(text)` 함수 — 재질문/정정 패턴 감지
  ```
  감지 신호: "다시", "틀렸", "아니야", "잘못됐", "그게 아니", "wrong" 등 13개
  ```
- `emit_skill_feedback(skill_name, success)` — 감지 시 SkillLifecycle에 자동 전달
- `response_handler.py` 응답 전 user_text 정정 신호 감지 → `record_feedback("_last_response", False)` 호출

**효과**: 스킬 성공률이 "예외 없음 = 성공"이 아니라 MJ 실제 피드백 기반으로 보정됨. "우연한 성공"이 반복 기록되지 않음.

---

### 규칙 7: "모델 탓하기 전에 내가 뭐라 시켰는지 보기" → Input Clarity Gate

**파일**: `modules/context_assembler.py`  
**조치**:
- `_input_clarity_score(text)` 함수 추가 — 모호성 점수 0.0~1.0
  - 1.0: 빈 입력
  - 0.9: 지시대명사 단독 발화 ("이거", "저거 해줘")
  - 0.8: 단순 긍정 단편 ("응", "ㅇ", "ok")
  - 0.6~0.7: 단편 + 대명사 혼합
- 점수 0.6+ 시 system 메시지 자동 주입:
  ```
  "[⚠️ Input Clarity Gate] 모호성 점수: 0.9. 이전 컨텍스트를 적극 참조하세요. 
   여전히 불명확하다면 되물어도 됩니다."
  ```

**효과**: LLM이 모호한 입력에서 컨텍스트를 더 적극적으로 참조. 엉뚱한 답 → 모델 탓 전에 입력 품질 먼저 점검하는 구조적 장치.
