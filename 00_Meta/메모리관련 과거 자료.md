## 1. consolidator_state.json 설치 및 경로 오류 해결

**작업일**: 2026-06-06 09:15  
**원인**: `memory_consolidator.py`가 시작 시 `consolidator_state.json`을 읽으려 하는데 파일이 없어 `FileNotFoundError` 및 `JSONDecodeError` 발생 → 메모리 엔진 초기화 정지

### 해결 방법

```bash
# 1. memory_engine 디렉터리 생성
mkdir -p ~/Applications/Mjauto/Scripts/hermes/memory_engine/

# 2. 빈 consolidator_state.json 생성
echo '{}' > ~/Applications/Mjauto/Scripts/hermes/memory_engine/consolidator_state.json
```

### 핵심 포인트
- `consolidator_state.json` 경로: `~/Applications/Mjauto/Scripts/hermes/memory_engine/consolidator_state.json`
- 파일이 없으면 `memory_consolidator.py`가 초기화 단계에서 크래시
- 내용은 빈 `{}` 로도 충분 — 첫 실행 시 자동으로 채워짐
- **메모리 엔진이 느려지거나 멈출 때 이 파일 확인이 1순위**

### 관련 파일
| 파일 | 경로 |
|------|------|
| `memory_consolidator.py` | `Scripts/modules/graph_memory/memory_consolidator.py` |
| `consolidator_state.json` | `Scripts/hermes/memory_engine/consolidator_state.json` |
| `bio_memory_engine.py` | `Scripts/modules/bio_memory_engine.py` |

## 2. 메모리 복구 이력 (2026-06-06)

**작업일**: 2026-06-06  
**증상**: Hermes WebUI 단기 기억 오염, 텔레그램 봇 응답 불일치

### 근본 원인

| 원인 | 내용 |
|------|------|
| **harness_memory.json 오염** | Telegram 봇과 WebUI가 동일한 `harness_memory.json`을 공유 → 서로의 대화가 섞임 |
| **환경변수 누락** | `.env`에 `ANTIGRAVITY_NVIDIA_API_KEY` 미등록 → 날씨 API 호출 실패 |

### 해결 절차

```bash
# 1. 오염된 단기 기억 파일 삭제
rm ~/Applications/Mjauto/Scripts/harness_memory.json

# 2. .env에 NVIDIA API 키 추가
echo 'ANTIGRAVITY_NVIDIA_API_KEY=your_key_here' >> ~/.hermes/.env

# 3. 게이트웨이 재시작
hermes gateway restart
# 또는
launchctl unload ~/Library/LaunchAgents/com.hermes.webui.plist
launchctl load  ~/Library/LaunchAgents/com.hermes.webui.plist
```

### 결과
- Hermes WebUI 정상 작동
- 텔레그램 봇 응답 일치 복원

### 향후 대책 (미적용 — 필요 시 구현)
- Telegram/WebUI 각각 별도 메모리 파일 사용:
  - `harness_memory_telegram.json`
  - `harness_memory_webui.json`
- `HERMES_HOME` 환경변수로 분리하는 방법도 가능

## 3. hermes_agent 메모리 확장 복구

**작업일**: 2026-06-06 전후  
**증상**: 메모리 엔진이 확장(L2 급증) 후 Early Exit 정체, L2 블로트

### Bio-Memory Engine v9.3 — 핵심 수정 내용 (2026-06-05)

| 파일 | 수정 내용 | 효과 |
|------|----------|------|
| `bio_memory_engine.py` | `_get_l2_bytes()` 메서드 추가 (402-405행), L2 KB/MB 실시간 보고 | L2 용량 모니터링 가능 |
| `dreamer_layer.py` | `offline_consolidation_forced()` 추가 (270-296행) — 중요도 하위 50% 강제 L3 전이, **1MB 초과 시 자동 발동** | L2 블로트 자동 해소 |
| `dreaming_v2.py` | 용량 위기 시 강제 증류 호출 (124-128행) + `_commit_to_l3_semantic()` atomic write (230-274행) | 데이터 손실 없는 안전한 L3 이전 |

### L2 급증 시 수동 강제 증류

```python
# Scripts/ 디렉터리에서 실행
from modules.dreamer_layer import DreamerLayer
dl = DreamerLayer()
dl.offline_consolidation_forced()  # L2 하위 50% 즉시 L3로 이전
```

### 메모리 상태 확인 명령어 (텔레그램)

```
/memory status   # L1/L2/L3 용량 현황
/memory sync     # L1→L2 즉시 동기화
/memory purge    # L2 강제 정리 (주의)
```

### 메모리 정지·느려짐 진단 체크리스트

1. `consolidator_state.json` 존재 여부 확인 → 없으면 `echo '{}' > ...` 생성
2. `harness_memory.json` 크기 확인 → 100KB 초과 시 삭제 후 재시작
3. `episodic_memory.json` (L2) 크기 확인 → 1MB 초과 시 강제 증류 실행
4. `bio_memory_config.json` 존재 여부 확인
5. `~/.hermes/runtime/memory/` 디렉터리 경로 확인
