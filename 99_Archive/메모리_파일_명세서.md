## 2. 오늘날의 3계층 JSON 메모리 (실현된 구조)

MJ님의 설계 개념이 실제로는 **JSON 기반 3계층 메모리 시스템**으로 구현되었습니다.  
아래 구조가 위 설계의 **L1~L3 저장소 계층**을 담당하며, 각각이 전담 모듈에 의해 관리됩니다.

### 메모리 5종 개요

| # | 파일명 | 계층 | 경로 | 용도 | 상태 |
|:---|:---|:---:|:---|:---|:---:|
| 1 | `memory.json` | *(구 L1)* | `Scripts/memory.json` | 구 HistoryManager 단기 버퍼 (harness_v2 시절) | **🪦 사망** |
| 2 | `harness_memory.json` | **L1 — 단기** | `Scripts/harness_memory.json` | 현재 활성 단기 대화 버퍼 | **✅ 활성** |
| 3 | `episodic_memory.json` | **L2 — 에피소딕** | `~/.hermes/runtime/memory/episodic_memory.json` | 중기 경험·사건 저장 | **✅ 활성** |
| 4 | `semantic_memory.json` | **L3 — 시맨틱** | `~/.hermes/runtime/memory/semantic_memory.json` | 장기 개념·패턴 저장 | **✅ 활성** |
| 5 | `bio_memory_config.json` | **설정** | `~/.hermes/runtime/memory/bio_memory_config.json` | 메모리 중요도·TTL 규칙 | **✅ 활성** |

```
설계 개념              실제 구현
─────────────────────────────────────────
hot.md (작업 캐시)  ← L1: harness_memory.json
                        + hot.md (Markdown)
memory.md (핵심 기억) ← L2: episodic_memory.json ~~— memory.md는 Dreaming 폐기로 정적화 (2026-05-27)~~
                        + L3: semantic_memory.json
                        + MEMORY.md / USER.md (Agent)
Journal (완전 기록)   ← wiki/30_Journal/*.md
```

### 3계층 관계도 (실현된 구조)

```
┌──────────────────────────────────────────────────────────────────────┐
│                     Hermes1 메모리 시스템 (3계층)                      │
├──────────────────────────────────────────────────────────────────────┤
│  L1: harness_memory.json (Scripts/)  — 11KB, 실시간 갱신              │
│  ├─ HistoryManager → Telegram 핸들러에서 읽기/쓰기                      │
│  ├─ bio_memory_engine.DeriverLayer → consolidation                    │
│  └─ graph_memory.MemoryConsolidator → Graph 추출                      │
│        │ 유휴 5분+ 감지 시                                            │
│        ▼                                                              │
│  L2: episodic_memory.json (.hermes/runtime/memory/)  — 610KB          │
│  ├─ DeriverLayer: L1→L2 consolidation (에피소드 추출)                   │
│  └─ DreamerLayer: L2→L3 추상화                                       │
│        │ Dreaming 사이클                                              │
│        ▼                                                              │
│  L3: semantic_memory.json (.hermes/runtime/memory/)  — 570B           │
│  └─ DreamerLayer → Skill Evolver 연동 (3회+ 패턴)                      │
│                                                                       │
│  bio_memory_config.json — 중요도/TTL/병합 규칙 제어                     │
│  🪦 memory.json — 사망 (5/15 이후 미갱신)                              │
└──────────────────────────────────────────────────────────────────────┘
```

## 3. Dreaming 프로세스

> **출처**: MJ님의 `(Hot.md파일관련)Memory_시스템_설계.md`

**실행:** 매일 새벽 3시 (dream_scheduler.py → ExecPlan 6단계)

**Dreaming 처리 흐름:**

```
1. Cronjob 실행 (dream_scheduler.py)
   ↓
2. hot.md 백업 생성 (hot.md.bak.{timestamp})
   ↓
3. hot.md 분석 (완료/진행중/핵심사항 분류)
   ↓
4. 처리 Draft 작성:
   - Journal에 추가할 완료 작업
   - ~~memory.md/L2에 추가할 핵심 요약~~
   - hot.md에서 삭제할 완료 항목
   ↓
5. Telegram으로 제안 → MJ님 승인/수정/취소
   ↓
6. 승인 시:
   - Journal 작성 (중복 제거)
   - L2 episodic_memory.json 갱신 + L3 semantic 추출
   - hot.md 정리
   ↓
7. 오류 시:
   - hot.md.bak로 복원
   - MJ님께 알림
```

```
    ↓
Antigravity 작업 → hot.md (외부업무) / MJ님 수동 추가
    ↓

    ↓
┌─────────────────────────────────────────────┐

```
