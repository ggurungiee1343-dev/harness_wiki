# 🛡️ 하네스 v2.2 지능화 및 감사 시스템 가이드

이 문서는 하네스(Harness) v2.2에 도입된 **에이전트 모드, 인제스트 엔진, 지식 감사 시스템, 그리고 Graphify 지식 그래프**의 메커니즘과 사용법을 설명합니다.

## 1. 에이전트 모드 (Agentic Execution)
하네스는 단순한 대화를 넘어 시스템 도구를 직접 사용하여 업무를 완수합니다.

### 🛠️ 주요 실행 태그
하네스가 답변 중 다음 태그를 포함하면 시스템에서 즉시 실행됩니다:
- `[SAVE: 폴더, 파일, 내용]`: 지정된 위치에 파일 저장 (타임스탬프 자동 포함).
- `[MOVE: 원본, 대상]`: 파일 이동.
- `[DELETE: 경로]`: 파일 삭제.
- `[LIST: 경로]`: 폴더 내 파일 목록 조회.
- `[READ: 경로]`: 파일 내용 읽기 (최대 1000자).
- `[MODULE: 이름, 코드]`: 새로운 Python 모듈 제작 및 저장.

---

## 2. 구조적 환각 방지 시스템 (Guardrails)
하네스는 `guardrails.md`의 통제를 받으며, 무작위 환각을 방지하기 위해 다음 4단계 안전장치를 가동합니다.
1. **명칭 일치 검증**: 존재하지 않는 에이전트 이름(예: Hermes) 등을 지어내지 않고, 원본 문서와 100% 일치하는 명칭만 사용.
2. **근거 추적 (Traceability)**: 사실을 주장할 때 반드시 문장 끝에 `[Source: 파일명]`을 출력하여 사후 정당화 차단.
3. **자아 비판 루프**: 텔레그램 출력 전, 논리와 명칭을 스스로 교차 검증.
4. **자율 행동 사전 검증 (Dry Run)**: 외부 태그(`[SAVE:]` 등)를 사용하기 전, 자신이 '무엇을, 어디에, 왜' 할 것인지 한 줄로 선 보고.

---

## 3. 지능형 인제스트 엔진 (Ingest Engine)
`Clippings` 폴더에 수집된 비정형 데이터를 정형화된 위키 문서로 자동 변환합니다.

### 📥 작동 방식
1. **명령**: "clippings ingest해줘" 또는 "지금 정리해"라고 지시.
2. **분석**: LLM이 제목 추출, YAML 프런트매터 생성, 본문 구조화를 수행.
3. **저장**: `20_Research` 폴더로 이관 후 원본 파일 삭제.
4. **정밀도**: 생성 시간을 시/분 단위(`created: YYYY-MM-DD HH:MM`)까지 기록.

---

## 4. 지식 감사 엔진 (Audit Engine)
위키 데이터의 일관성과 무결성을 매일 새벽 자동으로 점검합니다.

### 🔍 주요 점검 항목
- **끊긴 링크 확인**: `[[ ]]`로 연결되었으나 실제 존재하지 않는 문서 탐색.
- **지식 불일치 감지**: 연결된 파일 간의 최종 수정 시간(Timestamp)을 비교하여, 업데이트가 누락된 것으로 의심되는 파일을 보고.
- **[계획] Graphify 통합**: `graphify --update`를 호출하여 지식 그래프를 증분 갱신하고 고립 노드를 탐지.
- **보고 체계**: 매일 새벽 03:00 Dreaming 작업 시 수행되어 아침 텔레그램 리포트로 송신.

---

## 5. 타임스탬프 표준화 (Timestamp Standard)
모든 지식의 선후 관계를 파악하기 위해 **시/분 단위 정밀도**를 유지합니다.

- **형식**: `*최종 업데이트: YYYY-MM-DD HH:MM*`
- **자동 관리**: `file_manager.py`가 모든 저장 작업 시 문서 하단의 시간을 자동으로 갱신합니다.

---

## 6. Graphify 지식 그래프 (Knowledge Graph)

하네스 시스템 전체(코드 + 위키 문서)를 분석하여 **노드-엣지 지식 그래프**로 시각화합니다.

### 🗺️ 작동 흐름
```
코드(Scripts/) + 위키(wiki/)
        ↓
   Graphify 분석
        ↓
  ┌─────────────────────────────┐
  │  graph.html  ← 브라우저 시각화  │
  │  graph.json  ← GraphRAG 데이터 │
  │  GRAPH_REPORT.md ← 감사 보고서  │
  └─────────────────────────────┘
        ↓
  audit_engine.py → 아침 텔레그램 리포트
```

### 📊 결과물 설명
| 파일 | 용도 |
| :--- | :--- |
| `graph.html` | 브라우저에서 열면 인터랙티브 그래프. 노드 클릭/드래그 가능. |
| `GRAPH_REPORT.md` | God 노드(핵심 허브), 놀라운 연결, 탐색 추천 질문. |
| `graph.json` | GraphRAG/Neo4j 등 외부 연동용 원본 그래프 데이터. |

### 🕸️ 그래프 읽는 법
- **노드(원)**: 각 개념·함수·문서 하나
- **색상**: 같은 색 = 같은 커뮤니티 (밀접하게 연결된 그룹)
- **크기**: 클수록 더 많이 연결된 허브 노드 (= 핵심 파일)
- **엣지(선)**: 실선=명시적 관계, 점선=추론된 관계

### 🔄 자동화 통합 (계획)
`cron_manager.py`의 Dreaming(03:00) 작업에 통합 예정:
1. `audit_engine.py` → `graphify --update` 호출
2. 고립 노드, 끊긴 연결 탐지 → 기존 감사 리포트에 병합
3. 매일 아침 텔레그램으로 "지식 그래프 변경 요약" 수신

### 🚀 수동 실행 방법
Antigravity에게 아래처럼 요청:
```
"그래프 업데이트해줘"  →  graphify --update 실행
"전체 그래프 재분석해줘"  →  전체 재실행
```

## 💡 사용자 팁 및 UX 가이드
- **3단계 실시간 상태 보고**: 하네스가 명령을 처리할 때 더 이상 무작정 기다리지 않아도 됩니다. 메시지가 `🫡 지시 확인` → `🧠 엔진 가동 중(또는 🌐 웹 데이터 분석 중)` → `✅ 답변 완료` 순으로 실시간 업데이트됩니다.
- **하드웨어 시각 동기화 (Time-Sync)**: 두 비서 모두 박사님의 M4 맥 스튜디오 실제 서버 시각과 완벽히 동기화되어, 과거 기록에 얽매여 시차를 착각하는 일이 없습니다.
- **통합 관제 터미널 명령어**: 
  - 비서 생존 확인: `ps aux | grep _v2.py`
  - 하네스 생각 훔쳐보기: `tail -f ~/Applications/Mjauto/Scripts/harness.log`
  - 강제 재시작 (코드 업데이트): `pkill -9 -f _v2.py` (이후 launchd가 5초 뒤 자동 부활)
- **즉시 실행**: 예약된 시간을 기다리지 않고 지금 당장 정리를 원하시면 **"지금 dreaming 실행해"**라고 말씀하세요.
- **그래프 확인**: `open ~/Applications/Mjauto/graphify-out/graph.html` 또는 Antigravity에게 "그래프 열어줘" 요청.
