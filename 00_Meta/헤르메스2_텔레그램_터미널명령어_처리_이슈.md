# 헤르메스2 텔레그램 터미널 명령어 처리 이슈

**작성일:** 2026-06-01 11:35  
**관련 시스템:** Hermes2 (hermes2_bot.py / hermes_local.py)  
**심각도:** 🟡 — 기능 불편, 우회 방법 있음  

---

## 1. 증상

사용자가 Telegram 봇에 **터미널 명령어(raw shell command)**를 일반 텍스트로 전송하면:

1. 봇이 명령어를 **터미널 실행 없이** LLM에 채팅 메시지로 전달
2. LLM이 명령어 내용을 **텍스트 분석**만 하고 실제 실행 결과는 반환되지 않음
3. DeepSeek 모드는 아예 `RUN_CMD` 태그를 파싱하지 않아 영원히 실행 안 됨
4. Gemma4(로컬) 모드는 LLM 출력에 `[RUN_CMD: ...]` 태그가 포함되어야 실행되지만,
   - LLM이 **대괄호 없이** `RUN_CMD: sed ...` 형식으로 출력하면 정규식 미스매치
   - 실행되더라도 agentic loop(LLM→실행→LLM→...)로 느림

### 구체적 예시

**사용자 전송:**
```
grep -n "async def cmd_reduce" ~/Applications/Mjauto/Scripts/hermes_local.py
```

**DeepSeek 응답 (터미널 실행 없음):**
```
272번 줄이 cmd_dreaming_v89의 시작입니다. cmd_help 함수 종료 지점을 확인합니다.

RUN_CMD: sed -n '268,273p' /Users/bluesea/Applications/Mjauto/Scripts/hermes_local.py
```

→ LLM이 텍스트만 분석했을 뿐, `grep`은 **실제로 실행되지 않음**

## 2. 시스템 컨텍스트

### 2.1 DeepSeek 모드 — `hermes2_bot.py` (PID 93376)

```
사용자 (raw text)
  → handle_message() @ 330줄
    → _parse_nl_file_op() — 자연어 파일 작업 체크
      → 매칭 실패 (grep/sed는 파일 작업이 아님)
        → _query_gateway(text, mode, history) @ 415줄
          → LLM Gateway API 호출
            → LLM 응답 (텍스트 분석) → 그대로 사용자에게 전달
```

**핵심:** `hermes2_bot.py`에는 `RUN_CMD` 파싱/실행 로직이 **전혀 없음**. 단순 LLM 게이트웨이 호출만 수행.

### 2.2 Gemma4 로컬 모드 — `hermes_local.py` (PID 88333) + `harness_agent.py`

```
사용자 (raw text)
  → _base.py handle_text_message() @ 497줄
    → 자연어 의도 분류 → "chat"
      → harness_agent.handle_message() @ 624줄
        → LLM 호출 (채팅 응답 생성)
          → LLM 출력에 [RUN_CMD: ...] 태그 포함?
            → 예: execute_bash_command() 실행 @ 708줄
              → 결과를 LLM에 재주입 → 다시 분석 → (루프)
            → 아니오: 종료, 텍스트 응답만 전달
```

**핵심:** `harness_agent.py` 706줄 `re.search(r"\[RUN_CMD:\s*(.*?)\]", ans, re.DOTALL)` 로 태그 감지.  
**대괄호 `[...]` 누락 시 매칭 실패** → 명령어 미실행.

## 3. 근본 원인

### 3.1 LLM이 태그 형식을 정확히 준수하지 않음

시스템 프롬프트(`_FIXED_SYS_PROMPT` @ 34줄)에 `[RUN_CMD: 명령어]` 형식이 명시되어 있으나, LLM이 종종 **대괄호 생략**한 `RUN_CMD: 명령어` 만 출력함.

```python
# harness_agent.py 706줄 — 예상 형식
re.search(r"\[RUN_CMD:\s*(.*?)\]", ans, re.DOTALL)
# → "RUN_CMD: sed ..." (대괄호 없음) → None 반환 → 미실행
```

### 3.2 hermes2_bot.py에 RUN_CMD 파싱 로직 부재

`hermes2_bot.py`는 Telegram 메시지를 LLM 게이트웨이로 그대로 전달만 함.  
에이전틱 루프(태그 파싱 → 실행 → 재주입)가 없어 태그가 있어도 무시.

### 3.3 /exec 경로의 타입 버그 (hermes_local.py)

`handlers/_system.py` `cmd_exec()`에서 `execute_bash_command()`가 **문자열(str)**을 반환하는데,  
34-36줄이 **dict 메서드**로 접근:

```python
# _system.py 34-36줄 — BUG
stdout = exec_res.get('stdout', '')   # exec_res는 str → AttributeError
stderr = exec_res.get('stderr', '')
exit_code = exec_res.get('exit_code', -1)
```

→ `/exec` 명령어가 첫 번째 예외에서 crash 후 `except` 블록으로 빠짐.

## 4. 해결 방법 (사용자용)

**✅ `/exec` 명령어를 사용하세요.** LLM을 거치지 않고 직접 터미널 실행:

```
/exec grep -n "async def cmd_reduce" ~/Applications/Mjauto/Scripts/hermes_local.py && echo "✅ 추가됨" || echo "❌ 미추가"
```

두 봇 모두 `/exec` 지원:
- **hermes2_bot.py** 577줄: `subprocess.run()` 직접 호출, 60초 타임아웃
- **hermes_local.py** `handlers/_system.py`: `execute_bash_command()` async 호출, 30초 타임아웃

## 5. 향후 수정 제안 (코드)

### 5.1 hermes2_bot.py에 RUN_CMD 파싱 추가 (선택)
```python
# handle_message() 내, LLM 응답 후 RUN_CMD 태그 감지
m_cmd = re.search(r"\[RUN_CMD:\s*(.*?)\]", reply, re.DOTALL)
if m_cmd:
    import subprocess
    result = subprocess.run(m_cmd.group(1), shell=True,
                           capture_output=True, text=True, timeout=30)
    reply += f"\n\n[실행 결과]\n{result.stdout[:1000]}"
```

### 5.2 _system.py 타입 버그 수정
```python
# Before (BUG)
stdout = exec_res.get('stdout', '')
stderr = exec_res.get('stderr', '')
exit_code = exec_res.get('exit_code', -1)

# After (FIX — execute_bash_command는 str 반환)
```

## 6. 교훈

1. Telegram 봇에 raw 쉘 명령어를 보낼 때는 **반드시 `/exec` 접두어**를 사용할 것
2. `hermes2_bot.py`는 단순 LLM 게이트웨이 — 에이전틱 태그 실행 능력이 없음
3. `hermes_local.py`의 agentic loop는 `[RUN_CMD: ...]` 형식(대괄호 필수)에만 반응
