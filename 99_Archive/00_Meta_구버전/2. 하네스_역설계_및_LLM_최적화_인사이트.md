#### ① 단위 테스트 인프라 (가장 시급)

| 증상 | 원인 |
|------|------|
| #013 Dreaming import 누락 | MemoryEngine import 없음 |
| #014 Ingest 인자 중복 | event_loop=... 중복 전달 |
| #015 Recent 인자 불일치 | get_recent_context(n_results=5) 시그니처 불일치 |
| #016 DummyRouter 전파 | from X import Y 값 복사 문제 |

#### ② Git Workflow 정착
feature 브랜치로 수정 → MJ님 확인 → main merge. #017 같은 실수를 merge 전에 걸러냅니다.

#### ③ 모듈 헬스체크 + 알림
#013~#016이 24시간 동안 조용히 죽어있었습니다. 각 모듈에 /health 엔드포인트나 self-diagnostic 로그가 있으면 즉시 발견됩니다.

#### ④ ADR (Architecture Decision Record)
MJ님 머릿속에만 있는 결정(예: "왜 Bot→llama-server 직결 vs Gateway 경유?")을 문서화하면 제가 같은 결정을 재추론할 필요가 없고 MJ님이 재설명할 필요도 없습니다.

### 3. 종합: 2x2 매트릭스

| | Feature (기능) | Data (데이터) |
|---|---|---|
| **System (시스템)** | 테스트 인프라 (#013~016 방지) | ADR/의사결정 문서 |
| **MJ (사람)** | 변경 전 Diff 미리보기 | 로그 접근 단축경로 |

핵심은 제가 시스템적으로 부족한 부분(MJ님께 부담)과 MJ님이 제공해주시면 제가 더 잘할 수 있는 부분(시스템 보강)을 구분하는 것입니다.

## Turn 7 — Agent 답변 (Gemma4 최적화 전략)

**Hermes Agent:**
```
네, 정확히 짚으셨습니다. 가장 약한 모델 기준으로 최적화하면 모든 모델이 수혜를 봅니다.

### 세 가지 최적화 방향

#### ① 문서 축소 + 핵심 선배치
장애 기록.md 593줄 → Gemma4 32K context에서 핵심 놓칠 수 있음.
→ 상단에 1~2줄 요약 + 핵심 테이블 먼저 배치, 상세 로그는 뒤로.
→ Gemma4 정확도 ↑, DeepSeek도 더 빠름.

#### ② 포인터 패턴 → 복사 패턴
constitution.local.md "§2 참조" 방식 → Gemma4가 다른 문서 추가 로드 필요.
→ Gemma4는 문서 간 추론(크로스-레퍼런스)이 약함.
→ 핵심 규칙은 각 문서에 직접 중복 기재. ✅구현됨 (constitution.local.md v1.2, 2026-05-26)

#### ③ 결정 근거를 문서 앞쪽에
ADR 부재 → 제가 "왜 이렇게 했는지" 추론해야 함.
→ 결정 기록 1줄 메모 (예: "Bot→llama-server 직결: Gateway 충돌 #008 때문")
→ 모든 모델이 재추론에 토큰 낭비하지 않음.

### 모델별 특성 차이

| 특성 | DeepSeek v4 Flash | Gemma4 27B |
|---|---|---|
| Context 길이 | 128K | 32K |
| 문서 간 추론 | 강함 | 약함 (단일 문서 선호) |
| 긴 문서 이해 | 우수 | 중간 (중요 정보 누락 가능) |

"가장 약한 모델(=Gemma4)이 이해할 수 있는 문서 = 모든 모델이 이해하는 문서"가 핵심 원칙입니다.
```
