# 2026.05.08 업무일지

## Orchestrator-Worker 패턴 — 로컬 LLM 활용 고도화

외부 클라우드 AI가 내부의 구체적 실행을 지시하고 평가하는 구조. 이를 통해 $200 구독을 $20으로 낮춰도 사용한도가 충분해진다.

---

## 1. 핵심 개념: Opus가 생각하고, Sonnet이 작업한다

| 역할 | 기존 개념 | 우리 시스템 적용 |
|---|---|---|
| **Opus (계획자/오케스트레이터)** | 고급 클라우드 AI (Claude Opus 등) | Harness Agent (NVIDIA NIM) |
| **Sonnet (실행자/작업자)** | 비용 효율적 AI | Ollama (Qwen3 30B) |

**원리:**
- 오케스트레이터가 계획을 세우고, 구체적 지시를 생성
- 작업자가 지시를严格执行
- 오케스트레이터가 결과를 검증하고 정제

---

## 2. 우리 시스템에 적용した場合

### 동작 흐름
```
Harness (NVIDIA NIM) — 복잡한 계획, 지시 생성, 결과 평가
        ↓ (매우 구체적인 지시)
Ollama (Qwen3 30B) — 소스 분석, 문서 작성 등 실행
        ↓
Harness (NVIDIA NIM) — 결과 검증 및 정제
```

### 왜 우리 시스템에 적합한가?
- NVIDIA NIM DEGRADED/429 에러 시 Ollama가 백업
- 비용 절감: 일상 작업은 Ollama, 복잡한 건 NVIDIA NIM
- 로컬 LLM은 구체적 지시가 필요 — Harness가 상세 프롬프트 생성

---

## 3. 구체적 지시의 중요성

로컬 LLM (Sonnet 역的角色)은 지시가 구체적일수록 성능이 극대화된다.

### 예시: run_agent.py 분석

**단순 질문 (비권장):**
```
"run_agent.py 설명해줘"
```

**구체적 지시 (권장):**
```
"run_agent.py의 chat() 함수를 분석해서:
1. 함수 역할
2. 주요 파라미터
3. 내부에서 호출하는 함수 목록
위 3가지를 반드시 포함해서 500자 이내로 요약해줘"
```
