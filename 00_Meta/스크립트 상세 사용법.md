# 스크립트 상세 사용법

## 1️⃣ check_services.sh – 시스템 전체 현황 한눈에

```
bash ~/Applications/Mjauto/Scripts/check_services.sh
```

- **무엇을 검사하나요**
  1. **launchd plist** `com.bluesea.hermes_local.plist`, `com.bluesea.llama_server2.plist`, `com.bluesea.hermes_dreamer.plist` 상태 (loaded / exited / exit‑code).
  2. **포트·프로세스** `127.0.0.1:8080` (로컬 Gemma 4), `127.0.0.1:5000` (DeepSeek API 프록시), `127.0.0.1:9000` (nginx gateway) 가 열려 있는지.
  3. **API 키** 파일 존재 여부 (`~/Applications/Mjauto/keys/DEEPSEEK_API_KEY`, `~/Applications/Mjauto/keys/GEMMA4_TOKEN`).
  4. **디스크·메모리** `df -h` (남은 용량 ≥ 5 GB 권장), `vm_stat` (free pages ≥ 200 MB).
  5. **파일 무결성** `harness_memory.json`·`memory.json`·`harness_graph.json` 읽기 가능 여부.

- **출력 예시**

```
[OK]   launchd plist loaded: com.bluesea.hermes_local
[OK]   launchd plist loaded: com.bluesea.llama_server2
[WARN] launchd plist not loaded: com.bluesea.hermes_dreamer
[OK]   port 8080 listening (Gemma4)
[OK]   port 5000 listening (DeepSeek API)
[FAIL] port 9000 not listening (gateway)
[OK]   DEEPSEEK_API_KEY present
[WARN] GEMMA4_TOKEN missing
[OK]   /Users/bluesea has 12.3G free
[OK]   harness_memory.json readable
```

- **실패 시 대처**
  - `launchctl list | grep <plist>` 으로 상세 상태 확인.
  - 포트가 안 열리면 `launchctl bootout … && launchctl bootstrap …` 로 재시작.
  - 키 파일이 없으면 `cp <template> ~/.keys/...` 로 복사 후 `chmod 600`.
  - 디스크가 부족하면 `brew cleanup`·`rm -rf ~/Library/Caches/*` 로 공간 확보.

## 2️⃣ model_endpoint_check.sh – LLM 엔드포인트 가동 여부

```
bash ~/Applications/Mjauto/Scripts/model_endpoint_check.sh
```

- **검사 내용**
  1. **Gemma 4** (`http://127.0.0.1:8080/v1/models`) – HTTP 200 응답, `model` 필드에 `"gemma4"` 포함 여부.
  2. **DeepSeek Chat** (`https://api.deepseek.com/v1/models`) – `curl -s -H "Authorization: Bearer $DEEPSEEK_API_KEY"` 로 응답 검사.
  3. **NVIDIA NIM** (`http://127.0.0.1:5001/v1/models`) – 같은 방식으로 확인.

- **출력 예시**

```
[OK]   Gemma4 endpoint reachable, model=gemma4-26b
[OK]   DeepSeek endpoint reachable, model=deepseek-chat
[FAIL] NVIDIA NIM endpoint not reachable (connection refused)
```

- **실패 시**
  - **Gemma 4**: `launchctl list | grep llama_server2` 로 프로세스 확인 → `launchctl unload … && launchctl load …` 로 재시작.
  - **DeepSeek**: API 키가 올바른지 (`echo $DEEPSEEK_API_KEY | wc -c` ≥ 40) 확인, 네트워크 방화벽(`pfctl -s rules`) 검토.
  - **NVIDIA NIM**: `docker ps` 로 컨테이너 상태 확인, 포트 매핑(`docker inspect …`) 검증.

## 3️⃣ clear_webui_cache.sh – WebUI 모델 캐시 강제 재로드

```
bash ~/Applications/Mjauto/Scripts/clear_webui_cache.sh
```

- **동작 흐름**
  1. `~/.hermes/webui/models_cache.json` 파일을 삭제.
  2. 파일이 없으면 **WebUI**가 다음 재시작 시 `models` 엔드포인트를 호출해 최신 모델 목록을 다시 받아온다.
  3. **옵션**: 스크립트 마지막에 `open -a "Google Chrome" http://127.0.0.1:1234` 를 넣어 자동으로 WebUI를 열 수도 있다(주석 처리된 라인).

- **출력**

```
[OK]   cleared cache file: /Users/bluesea/.hermes/webui/models_cache.json
```

- **왜 쓰나요**
  - `config.yaml` 에 `model: gemma4` 등 변경했지만 WebUI 드롭다운이 그대로 옛 모델을 보여줄 때.
  - 캐시가 손상돼 모델 이름이 누락될 때 (예: `model list` 가 빈 배열).

- **주의**
  - 캐시 파일을 지우면 **WebUI 초기 로드 시** 잠시(≈ 2 초) 응답이 느려질 수 있다.
  - 파일이 이미 없으면 `[WARN] cache file not found` 로 무시하고 종료한다.

## 4️⃣ check_venv_patches.sh – pip upgrade 후 핵심 패치 존재 여부 검증

```
bash ~/Applications/Mjauto/Scripts/check_venv_patches.sh
```

- **점검 항목**
  | 파일 | 확인 문자열 | 의미 |
  |------|---------------|------|
  | `~/Applications/Mjauto/Scripts/harness_agent.py` | `openai/gpt-oss-120b` | 최신 LLM 모델 호출이 코드에 반영됐는지 |
  | `~/Applications/Mjauto/Scripts/run.py` | `launchctl kickstart` | 서비스 재시작 로직 포함 여부 |
  | `~/Applications/Mjauto/.hermes/config.yaml` | `toolsets:` | 전체 도구가 활성화돼 있는지 (빈 리스트이면 비활성) |

- **출력 예시**

```
[OK]   harness_agent.py: model patch present (openai/gpt-oss-120b)
[OK]   run.py: launchctl kickstart command present
[OK]   config.yaml: toolsets entry present
```

- **실패 시**
  - **패치 누락**: `[FAIL] harness_agent.py: missing model patch`. 해결: `git checkout -- harness_agent.py` 로 원본 복구 후 `sed -i '' 's/.../.../'` 로 패치 재적용.
  - **run.py** 에 `launchctl` 호출이 없으면 자동 재시작이 안 된다 → `grep -q "launchctl kickstart" run.py || echo "INSERT"` 로 삽입 스크립트 작성.
  - **config.yaml** 에 `toolsets:` 가 비어 있으면 `sed -i '' 's/toolsets:.*/toolsets: [web, terminal, file, delegate]/' ~/.hermes/config.yaml` 로 복구.

---

### 공통 사용 팁
- **실행 권한**: `chmod +x ~/Applications/Mjauto/Scripts/*.sh`
- **로그 보관**: `bash ~/Applications/Mjauto/Scripts/check_services.sh 2>&1 | tee -a ~/Applications/Mjauto/logs/check_services_$(date +%Y%m%d).log`
- **cron 등록**: 필요 시 `launchd` 플리스트에 `StartInterval` 지정.
- **디버깅**: 스크립트에 `set -euo pipefail` 로 오류 즉시 중단, `echo "DEBUG: $(command)"` 로 중간값 출력.
- **환경 변수**: API 키를 `export DEEPSEEK_API_KEY=$(cat ~/Applications/Mjauto/keys/DEEPSEEK_API_KEY)` 로 설정하면 스크립트가 자동 사용.
