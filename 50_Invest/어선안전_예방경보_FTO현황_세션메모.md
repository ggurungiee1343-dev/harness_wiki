# 어선안전 예방경보 시스템 — FTO(자유실시조사) 현황 및 세션 인계 메모

> 이 문서는 원래 Claude Code 메모리(`project_fishing_vessel_patent_fto.md`)의 스냅샷이었으나, 2026-07-11 보안상 이유로 메모리 원본은 삭제하고 이 wiki 사본만 최신 내용(rev.7.10까지)으로 갱신해 보존합니다. 이제 이 파일이 유일한 최신본입니다.

2026-07-11 기준, 어선안전 예방경보 시스템 발명제안서 관련 정식 FTO는 아직 시작 전이며 아래 항목들이 다음 세션 인계 대상.

**Why**: 변리사 정식 제출(FTO 포함) 전 단계 — 지금까지의 조사는 전부 Claude/MJ님의 예비조사(KIPRIS·Google Patents·J-PlatPat 개별 검색) 수준이며 법적 효력이 있는 정식 조사가 아님. 서류에 빈칸이 남아있고 방어 논리는 미검증 상태.

## 🔴 우선 확인 필요
- **정식 FTO 전무**: 국내 6건·일본 8건만 원문 대조, 미국·중국·유럽은 신규성 선행자료 확인 수준에 그침. 변리사를 통한 정식 FTO 아직 미착수.
- **J-PlatPat 일본 검색 = 전수조사 아님, DIY 시도는 2026-07-09 세션에서 포기**: 4개 키워드 조합(2026-07-08) + IPC/키워드 조합 다수(2026-07-09) 시도. 로그인 계정 없어 CSV 일괄추출 불가.
- **확정 원인(2026-07-09, 여러 차례 재현 검증 완료): `[船舶/TX]`를 다른 전문(TX) 키워드와 AND로 묶으면 J-PlatPat이 항상 깨짐** — 결과가 배와 무관한 최신 특허 나열(NTT도코모 통신·WGR 안테나·블록체인 등)로 대체됨. 단어 개수(2개~4개) 무관하게 재현됨. 반대로 `船舶` + **IPC 분류코드**(예: G08B25/00) 조합이나, `船舶` 없이 전문 키워드만 조합(예: `DSC*チャンネル70*警報`, 2건 — 선상 낙수사고 안전시스템, 관련성 있음)한 경우는 정상 작동. 원인은 J-PlatPat 자체의 엔진 버그로 추정(우리 쪽 문제 아님). `船舶` 제외하고 키워드만 조합하면 결과가 200건 이상으로 너무 넓어져 수작업 분류 불가 — FI별 필터(B63 등) 후처리도 시도했으나 MJ님이 이 경로는 비효율적("생 노가다")이라 판단해 **DIY J-PlatPat 재검색은 2026-07-09부로 중단**.
- **확보한 유효 결과 2건**: ①`甲板*機関室*警報`(48건, B63B/B63H 선박공학 위주 — 구버전 비필드코드 형식이 우연히 작동), ②`DSC*チャンネル70*警報`(2건, 선상 낙수사고 안전시스템 — 정확도 높음). 두 결과 모두 본 발명(다중구역 강제경보+검증+로그)과 정확히 일치하는 선행기술은 미발견.

## ✅ rev.7.7 반영 완료(2026-07-09) — 청구항 상위개념화 실행 (MJ님 "두리뭉실하게" 원칙 적용)
MJ님 우려("기술 스펙을 너무 자세히 적으면 경쟁사가 우회함")를 청구항 본문에 실제 적용: 독립항1·방법항10의 발현 검증을 "전류 또는 부하 변화 감지"→"경보 출력이 물리적으로 실제 발현되었는지 여부를 검증"으로 확장, 전류 되먹임은 신설 청구항12로 종속 배치(총 12항). Sonnet 제안을 Fable이 3가지 보정 후 실행: ①명칭 "발현 검증부" 유지(상호참조 보존) ②전류센싱을 버리지 않고 종속항으로(후퇴선 확보) ③방법항도 동반 수정(구멍 방지). 명세서·요약의 구체 기재는 의도적으로 유지 — 상위개념 청구항의 뒷받침 요건이자 종속항 근거(두리뭉실은 청구항에서, 상세함은 명세서에서가 특허 문서의 정석 구조). 검토요청 12-a는 "선반영 완료+기능식 문언의 한정해석 리스크 검토 요청"으로 갱신. 관련 배경: MJ님이 문답 파일에서 제기한 "검토요청 12번이 변리사에게 패를 보여주는 것 아닌가" 우려는 Fable이 "사전 억지가 사후 반박보다 유리"로 판단해 상세 유지 — 이 판단은 MJ님 원 우려를 뒤집은 것이므로 변리사 미팅 전 최종 재확인 여지 있음.

발명제안서를 특허 작성 표준절차(SOP)에 대조해 5개 취약점 발견. MJ님 판단으로 서지사항 공백(출원인·발명자)은 "변리사 상담 중 채우면 됨"으로 무시 확정.
- **최종 반영(유지)**: 거절이유 4번 신설 — §102 신규성 단독 방어논거(5축 대비표 기준 "검증"+"증명(로그)" 축을 동시 개시하는 문헌 없음).
- **되돌림(2026-07-11, MJ님 지적)**: 검토요청 14번(우선심사/PPH 심사가속 제도) — "특허등록 안 될 수도 있는데 너무 앞선 판단, 그에 대한 계획도 정확히 안 잡혔다"는 이유로 반영 취소·삭제. **교훈**: SOP 부록D(심사가속 옵션)는 등록 가능성이 어느 정도 확보된 이후 검토할 사안이지, 초안 단계에서 선제적으로 변리사에게 묻기엔 이르다 — SOP를 실제 발명에 기계적으로 적용하지 말고 그 발명의 현재 단계(아직 등록 여부 불확실)에 맞는 항목만 선별할 것.
- 미반영 2건(대체검증수단 종속항 미비, 인용문헌 특허패밀리 확인 편차)은 변리사 정식 검토 영역으로 남김.

## ✅ rev.7.10 반영 완료(2026-07-11) — [0037] "광학 센서·진동 센서" 근거 없음 확인 후 삭제
명세서 [0037]의 발현검증 대체수단 중 "광학 센서(경광등 점등 감지)"와 "진동 센서"는 통합본 v8.2·문답법 파일·FTO세션메모·특허등록전략분석 4개 문서 전체를 grep했으나 어디에도 근거를 찾을 수 없어 삭제. rev.7.8에서 "방어적 공개" 명목으로 근거 없이 임의 추가된 것으로 추정.
- **전압 감지는 유지**: MJ님이 "전류·전압 차이로 VTS 신호 수신 여부를 기록하는 게 기술적으로 안 되는가"로 재질의 → [0037-2] 수식(V(t)=R_eq·i_fb(t)+L_eq·di_fb(t)/dt+K_emf·v_cone(t))이 애초에 전압-전류 결합 관계식이라, "구동전류 일정 유지 + 인가전압 측정"은 전류센싱과 동일 역기전력 원리의 다른 측정 포인트일 뿐임을 확인 — 전압은 남기고 광학·진동만 삭제하는 것으로 결론(검토요청 12-a 문구도 동반 수정).
- **개념 명확화**: 전류/전압 검증은 "VTS 신호 수신 여부"가 아니라 "수신 이후 스피커가 실제로 소리를 냈는지(발현 여부)"를 확인하는 것. 신호 수신 자체는 디지털 패킷이라 이진값으로 자명하고 별도 검증 불필요 — 이 구분을 다음 세션에서도 헷갈리지 않도록 기록.
