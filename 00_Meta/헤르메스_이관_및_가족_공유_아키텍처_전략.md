# 🕸️ 헤르메스(Hermes) V2.5+ 미래 이관 및 가족 공유를 위한 아키텍처 전략 보고서

기존 헤르메스 에이전트의 기본 기능(자체 `memory.md`, `user.md`, Kanban, 멀티 에이전트 협업 등)과 현재 우리가 커스텀하게 붙여놓은 자동화 스크립트(`ingest`, `dreaming`, `wiki_linker` 등)가 중복되거나 충돌하면, 파일이 중구난방으로 쌓이고 엔진 업그레이드 시 이관 비용이 극도로 커질 수 있습니다.

또한, **가족들에게 이 시스템을 분배(배포)하여 쉽게 이관**할 수 있도록 지금부터 구조를 표준화해야 합니다. 이를 위한 핵심 대비 전략과 마일스톤을 정리합니다.

---

## 🎯 1. 기능 중첩 방지 및 단일 진실 공급원(SSOT) 확립

헤르메스 에이전트가 자체 업데이트되더라도 데이터의 정합성이 유지되려면 **데이터(옵시디언)와 로직(파이썬 스크립트)을 완벽히 분리**해야 합니다.

### 1) 데이터 영역의 단일화 (SSOT)
*   **원칙**: 헤르메스 엔진의 버전에 관계없이 **"박사님의 옵시디언 보관소(`Mjobsidian`)"**가 최종 데이터 저장소(Single Source of Truth)가 되어야 합니다.
*   **대비책**:
    *   헤르메스 에이전트가 내부적으로 사용하는 `memory.md`, `user.md` 파일의 위치를 옵시디언 내 `00_Meta` 폴더로 리다이렉션(심볼릭 링크 또는 환경변수 설정)하여 통합 관리합니다.
    *   이로써 에이전트가 교체되어도 쌓인 지식(`memory.md`, `Journal`, `hot.md`)은 온전히 옵시디언에 보존됩니다.

### 2) 칸반(Kanban) 및 멀티 에이전트 연동
*   헤르메스의 멀티 에이전트 기능(기획자, 칸반 매니저, 개발자 등)이 문서를 수정할 때도, 우리가 앞서 구축한 `file_manager.py`의 자동 꼬리말 타임스탬프 로직이나 `wiki_linker`를 API 형태로 가져다 쓰도록 인터페이스를 통합합니다.
*   커스텀 모듈들을 독립된 라이브러리(`modules/`)로 패키징해 두었으므로, 헤르메스가 업데이트되어도 엔진 진입점(Entry Point)에서 모듈을 임포트해 호출하기만 하면 됩니다.

## 🚀 2. 헤르메스 코어 업데이트 대비 (미래 이관 보호 전략)

헤르메스 에이전트가 신규 버전으로 업그레이드될 때 셋팅이 리셋되는 문제를 예방하기 위한 **플러그인/모듈 아키텍처**를 적용합니다.

1.  **코어 코드 수정 금지 (Hooks 패턴)**:
    *   `hermes_local.py` 본체를 직접 수정하는 대신, `custom_plugins/` 폴더를 만들어 우리가 커스텀한 명령어 `/web`, `/cove`, `/clip` 등)를 별도 파일로 분리합니다.
    *   헤르메스 코어가 실행될 때 `custom_plugins/` 내부의 플러그인을 자동으로 로드하도록 설계하면, 헤르메스 소스 코드가 최신 버전으로 통째로 업데이트되어도 **플러그인 폴더만 그대로 유지하면 셋팅이 100% 보존**됩니다.
2.  **모든 경로의 환경변수화 (`.env`)**:
    *   현재 스크립트 곳곳에 들어가 있는 `/Users/bluesea/...`와 같은 절대 경로를 모두 배제하고 `VAULT_PATH` 등의 환경변수로 일원화합니다.

## 👨‍👩‍👧‍👦 3. 가족 공유를 위한 패키징 & 배포 전략 (Portability)

가족들에게 이 텔레그램 비서 시스템을 분배하기 위해서는 **"한 번에 설치되고 쉽게 설정할 수 있는 패키지"**로 표준화되어야 합니다.

### 1) 환경 변수 기반 멀티테넌시(Multi-tenancy) 구조 설계
가족 구성원마다 개별 텔레그램 봇과 개별 옵시디언 보관소를 갖게 되므로, 설정 파일(`.env`) 하나만 복사해서 적어넣으면 실행되는 구조로 만듭니다.

**📋 가족 배포용 설정 템플릿 예시 (`.env.template`):**
```env
# 텔레그램 연결 정보
TELEGRAM_BOT_TOKEN=family_member_bot_token_here
ALLOWED_USER_ID=family_member_chat_id_here

# 개인 문서고 정보
VAULT_PATH=/Users/family_username/Documents/ObsidianVault

# AI 추론 엔진 설정
GEMINI_API_KEY=api_key_here
DEFAULT_LLM_MODEL=gemini-2.5-flash

# 환경 설정
TIMEZONE=Asia/Seoul
```

### 2) 배포 가방(Boilerplate) 패키지 구성
가족에게 공유해 줄 최종 배포 폴더는 다음과 같이 정형화된 구조를 띱니다.

```text
📦 Hermes_Family_Package/
 ┣ 📂 config/               # .env 설정 파일
 ┣ 📂 core/                 # 헤르메스 엔진 소스코드 (손대지 않음)
 ┣ 📂 custom_plugins/       # 우리가 개발한 기능 모듈 (ingest, linker 등)
 ┣ 📂 obsidian_template/    # 달력, meta, 저널 등 기본 폴더 구조가 세팅된 빈 옵시디언 보관소 템플릿
 ┣ 📜 setup.sh              # 클릭 한 번으로 파이썬 라이브러리 및 Launchd(맥) 등록을 해주는 설치 스크립트
 ┗ 📜 README.md             # 초보자용 가이드북
```

### 3) 간편 설치 스크립트 (`setup.sh`) 제공
*   가족이 맥 터미널에서 `./setup.sh`만 실행하면 파이썬 라이브러리 설치부터 launchd(백그라운드 자동 실행) 등록까지 완전 자동으로 완료되도록 유틸리티 스크립트를 빌드하여 배포 편의성을 확보합니다.

## 📋 4. 향후 실행 로드맵 (Action Items)

다음 세션에서 박사님과 함께 이 전략을 구체화할 때 진행할 태스크 우선순위입니다:

*   **1단계: 절대 경로 제거 및 `.env` 완전 격리**: `file_manager.py`, `ingest_engine.py` 등 모든 파일에서 `/Users/bluesea` 문자열을 완전히 걷어내고 환경변수에서 가져오도록 리팩토링.
*   **2단계: 플러그인 로더(Plugin Loader) 구축**: `hermes_local.py`가 특정 폴더 내 커스텀 명령어 스크립트를 동적으로 읽어들이는 기능 추가 (코어 업그레이드 대비).
*   **3단계: 옵시디언 템플릿 및 배포 패키지 구성**: 가족들이 즉시 사용할 수 있도록 빈 폴더 구조의 템플릿과 설정 스크립트 초안 작성.
