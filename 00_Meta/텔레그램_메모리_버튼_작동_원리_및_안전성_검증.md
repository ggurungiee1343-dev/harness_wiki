### A. 메모리 정리 콜백 로직 ([_base.py : L101-124](file:///Users/bluesea/Applications/Mjauto/Scripts/handlers/_base.py#L101-L124))
```python
    # === 메모리 캐시 정리 (sudo purge) ===
    if data == 'mem_purge_confirm':
        await query.edit_message_text('🧹 메모리 캐시 정리 중... 잠시만 기다려 주세요.')

                f'▸ **확보된 램: `{recovered:.1f} GB`** 🥳\n\n'
                f'현재 진짜 여유 공간: `{after["free_gb"]:.1f} GB`'
```

### B. 메모리 통계 계측 로직 ([_base.py : L307-343](file:///Users/bluesea/Applications/Mjauto/Scripts/handlers/_base.py#L307-L343))
```python
async def _get_mem_info() -> dict:
    """vm_stat 파싱 → 메모리 통계 dict 반환"""
    total_proc = await asyncio.create_subprocess_shell(
        'sysctl hw.memsize', stdout=subprocess.PIPE, stderr=subprocess.PIPE
    )
    total_out, _ = await total_proc.communicate()
    total_bytes = int(total_out.decode().strip().split(':')[1].strip())
    total_gb = total_bytes / (1024 ** 3)

    vm_proc = await asyncio.create_subprocess_shell(
        'vm_stat', stdout=subprocess.PIPE, stderr=subprocess.PIPE
    )
    vm_out, _ = await vm_proc.communicate()
    vm_lines = vm_out.decode().strip().split('\n')

    page_size = 16384
    stats = {'free': 0, 'active': 0, 'wired': 0, 'cached': 0}
    for line in vm_lines:
        if 'Pages free' in line:
            stats['free'] = int(line.split(':')[1].strip().rstrip('.'))
        elif 'Pages active' in line:
            stats['active'] = int(line.split(':')[1].strip().rstrip('.'))
        elif 'Pages wired down' in line:
            stats['wired'] = int(line.split(':')[1].strip().rstrip('.'))
        elif 'File-backed pages' in line:
            stats['cached'] = int(line.split(':')[1].strip().rstrip('.'))

    to_gb = lambda pages: (pages * page_size) / (1024 ** 3)
    used_gb = to_gb(stats['active'] + stats['wired'])
    return {
        'total_gb': total_gb,
        'used_gb': used_gb,
        'used_pct': (used_gb / total_gb * 100) if total_gb > 0 else 0,
        'cached_gb': to_gb(stats['cached']),
        'free_gb': to_gb(stats['free']),
    }
```

## 2. 🛡️ 시스템 안전성 및 부작용 검증

결론적으로 이 기능은 **컴퓨터 하드웨어, OS(macOS), 개인 파일에 아무런 손상을 입히지 않는 안전한 표준 최적화 작업**입니다.

### A. 데이터 유실 방지 설계 (`sync` 명령어의 역할)
* 버튼 클릭 시 단순히 캐시만 날리는 것이 아니라 **`sync` 명령어가 선행 실행**됩니다.
* `sync`는 현재 메모리에 임시 보관 중인 unwritten 버퍼 데이터(사용자가 수정한 파일, 앱 상태 등 아직 SSD 디스크에 완전히 기록되지 않은 내용)를 **디스크에 강제로 완벽하게 쓰고 저장**시킵니다.
* 따라서 정리 실행 시점에 작성 중이던 텍스트나 파일이 깨지거나 날아갈 걱정이 전혀 없습니다.

### B. macOS 메모리 구조와 `purge` 명령어의 관계
* **File-backed pages(캐시 램)**: macOS는 최근 읽어 들인 파일(위키 스캔, 소스 코드 파싱 등)을 다음 번에 빠르게 열기 위해 램의 일부를 파일 임시 보관함으로 전용합니다. 이 캐시의 크기가 점차 누적되어 12~16GB 이상을 차지하게 됩니다.
* **`sudo /usr/sbin/purge`**: 이 명령은 macOS 커널에 지시하여 **현재 비활성화(Inactive)되어 있는 모든 파일 디스크 캐시 페이지를 즉시 Flush(초기화)하여 진짜 빈 메모리(Free RAM) 영역으로 환원**시킵니다.
* 이는 애플이 macOS 시스템 관리자를 위해 기본 제공하는 공식 시스템 유틸리티입니다. 프로세스(실행 중인 앱)를 강제 종료(kill)하여 동작을 정지시키는 구조가 아니므로 안전합니다.

### C. 발생 가능한 미세한 영향 (Side Effect)
* **최초 파일 로드 레이턴시**: 캐시를 정리한 직후에 특정 파일이나 대용량 앱을 다시 처음 열 때, RAM 캐시 대신 로컬 SSD 디스크에서 파일을 새로 읽어와야 하므로 아주 미세한 수준의 로딩 속도 차이가 있을 수 있습니다.
* **무해함**: Mac Studio의 내부 SSD 속도가 압도적으로 빠르기 때문에 사용자가 실감하기는 불과 0.0x초 단위 수준이며, 1회 열리고 나면 다시 OS가 캐시를 차곡차곡 쌓으므로 시스템 성능 저하는 수초 이내에 사라집니다.

## 3. ⚙️ 로컬 LLM (llama-server) 추가 리소스 관리 가이드

텔레그램 메모리 정리 버튼을 통한 캐시 해제와 별개로, 로컬에서 상시 기동 중인 `llama-server` (Gemma 4 26B 로드 중)는 **약 10.5 GB의 RAM(RSS)**을 항상 고정 점유합니다. 

만약 딥시크(DeepSeek) API를 주로 사용하여 로컬 Gemma 4 모델을 장기간 사용하지 않으신다면, 이 백그라운드 서비스를 정지시킴으로써 10.5 GB의 램과 GPU VRAM을 완벽히 확보할 수 있습니다.

### A. Llama-Server 백그라운드 서비스 일시 정지 (RAM 10.5GB 즉시 확보)
텔레그램의 `/exec` 명령어 또는 Mac 터미널에서 아래 명령을 실행합니다.
```bash
launchctl unload ~/Library/LaunchAgents/com.bluesea.llama_server2.plist
```

### B. Llama-Server 서비스 재개 (필요 시 복구)
로컬 Gemma 4 모델을 다시 사용하여 추론하고 싶으실 때는 아래 명령을 가동합니다.
```bash
launchctl load ~/Library/LaunchAgents/com.bluesea.llama_server2.plist
```
